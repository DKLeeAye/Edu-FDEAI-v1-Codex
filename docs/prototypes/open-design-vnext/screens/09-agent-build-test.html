Production Dify Build

先创建知识库，再把检索能力接入正式 Chatflow。

正式项目不是只在 Chatflow 中添加一个检索节点。学生需要先在 Dify 知识库完成资料上传、分段清洗、索引方式和检索参数配置，确认知识库创建成功后，再回到 Chatflow 完成业务边界、引用回答、转人工分支和发布回填。

本页产物 正式知识库 + 正式 Chatflow + 平台同步记录

完成 12 个构建步骤后，学生需要提交知识库名称、文件清单、分段清洗配置、索引与检索配置、节点连线、Prompt 摘要、Dify 发布链接和 Preview 预检记录。

Target Build Path

目标结构：知识库配置先完成，Chatflow 只负责调用与编排。

截图里的分段最大长度、重叠长度、文本预处理、索引方式和 Top K 都属于知识库创建过程。Chatflow 中的知识检索节点应调用这个已配置好的知识库。

KB-01 创建知识库

进入 Dify 知识库，选择导入已有文本并新建质检追溯知识库。

KB-02 上传资料

上传 SOP、MES 导出、Excel 台账、整改报告和审厂材料。

KB-03 分段清洗

配置分段标识符、最大长度、重叠长度和文本预处理规则。

KB-04 索引检索

配置索引方式、检索方式、Top K，并确认处理完成。

CF-01 开始节点

接收用户问题 query，并作为检索查询变量传递。

CF-02 知识检索

调用已创建的质检追溯知识库，不在此处重新配置建库参数。

CF-03 边界判断

根据证据是否充分、是否越界，决定回答或转人工。

CF-04A 引用回答

基于检索证据组织答复，并说明来源。

CF-04B 资料不足 / 转人工

提示缺口、记录原因，不编造责任结论。

CF-05 发布与回填

发布应用链接，交给 EduFDE 自动化测试。

01

创建正式项目 Chatflow 应用。

目标：在 Dify 中新建正式应用，保留默认开始节点，后续用于接入已创建的知识库。

Dify 中这样做

  1. 在工作室点击 创建空白应用，类型选择 Chatflow。
  2. 应用名称建议为：制造业质检追溯 AI 助手。
  3. 应用描述写清楚：面向审厂追溯、质检记录查询和资料缺口提醒。
  4. 进入画布后先保存应用，后续再逐步添加知识检索和分支节点。

同步到平台

02

进入 Dify 知识库，创建质检追溯知识库。

目标：先建立知识库容器，后续分段、索引和检索参数都在这里完成。

Dify 中这样做

  1. 切换到顶部导航的 知识库。
  2. 点击创建知识库，选择 导入已有文本。
  3. 知识库名称建议为：制造业质检追溯知识库 v1。
  4. 不要选择 Notion 或 Web 同步；本项目先使用课程整理后的质检资料文件。

同步到平台

03

上传制造业质检资料文件。

目标：把阶段三筛选后的资料上传到 Dify，而不是把未经判断的原始资料全部放进去。

Dify 中这样做

  1. 在“选择数据源”页选择 导入已有文本。
  2. 上传教师提供的 SOP、MES 导出、Excel 台账、整改报告或审厂材料。
  3. 确认每个文件名称清晰，能反映批次、工序、标准或资料类型。
  4. 如果文件中仍有纸质 OCR 错误或图片未标注，先回到阶段三记录为待处理，不直接进入正式知识库。

同步到平台

04

配置文本分段与清洗规则。

目标：根据资料类型配置分段标识、最大长度、重叠长度和文本预处理规则。

Dify 中这样做

  1. 进入 文本分段与清洗 页面。
  2. 选择通用或父子分段模式；SOP 和标准条款优先保持标题层级。
  3. 记录分段标识符，例如换行、标题符号或标准条款编号。
  4. 设置分段最大长度和重叠长度；参考前一页分块策略，不机械套默认值。
  5. 按需启用文本预处理，例如替换连续空格、换行符、制表符；不要删除有意义的批次号或标准编号。

同步到平台

05

配置索引方式、检索设置并完成处理。

目标：在知识库创建阶段完成索引与检索基础配置，确认 Dify 显示处理完成。

Dify 中这样做

  1. 选择索引方式。高质量模式更适合正式质检追溯，经济模式仅用于练习或低风险资料。
  2. 配置检索设置，例如倒排索引、Top K 和是否使用混合检索。
  3. 点击保存并处理，等待 Dify 显示 处理完成 / 知识库已创建。
  4. 在处理完成页核对知识库名称、分段模式、最大长度、预处理规则、索引方式和检索设置。

同步到平台

06

在 Chatflow 中接入知识检索节点。

目标：把已创建的知识库连接到正式 Chatflow，而不是在节点里重新做建库配置。

Dify 中这样做

  1. 回到正式 Chatflow 应用画布。
  2. 在开始节点后新增 知识检索 / Knowledge Retrieval 节点。
  3. 选择刚创建成功的 制造业质检追溯知识库 v1。
  4. 确认检索查询使用开始节点的 query 变量。
  5. 检查节点输出是否会传给后续边界判断和 LLM 节点。

同步到平台

07

配置业务边界判断分支。

目标：把阶段三风险边界变成 Chatflow 中可执行的条件分支。

Dify 中这样做

  1. 在知识检索节点后新增 条件分支 / IF-ELSE 节点。
  2. 分支一：检索结果充分且问题属于质检追溯范围，进入引用回答。
  3. 分支二：证据为空、记录冲突、涉及责任判定或处罚建议，进入资料不足/转人工回复。
  4. 如果 Dify 当前条件表达式不支持复杂判断，可先用 LLM 分类节点或变量标记辅助判断。

同步到平台

08

配置引用回答 LLM 节点。

目标：让智能体基于检索证据回答，并明确来源、缺口和待确认事项。

建议 Prompt 结构

你是制造业质检追溯 AI 助手。
任务：回答批次、工序、缺陷、整改和审厂材料准备相关问题。
证据：只能使用知识检索节点返回的内容。
引用：回答必须列出来源文件、批次号、工序或标准条款。
边界：资料不足、记录冲突、责任判定、处罚建议必须提示人工确认。
格式：先给结论，再列证据来源，最后列待确认事项。
  1. 点击引用回答路径中的 LLM 节点。
  2. 把知识检索结果作为上下文变量传入。
  3. 将角色、证据、引用、边界和格式要求写入指令。
  4. 在 Preview 中确认回答不会脱离证据。

同步到平台

09

配置资料不足与转人工回复。

目标：让智能体在无法可靠回答时给出合规提示，而不是继续生成看似完整的答案。

Dify 中这样做

  1. 在边界分支的异常路径后新增 直接回复 或 LLM 节点。
  2. 资料不足时说明缺少哪些字段或证据，例如批次号、异常原因、复检结果。
  3. 记录冲突时并列证据来源，提示质量负责人确认。
  4. 责任判定、处罚建议、客户承诺类问题必须转人工。

同步到平台

10

检查节点连线与变量传递。

目标：确认用户问题、检索结果和回答输出在 Chatflow 中完整流转。

需要逐项检查

  1. 开始节点 query 是否进入知识检索节点。
  2. 知识检索结果是否进入边界分支和引用回答 LLM。
  3. 引用回答路径是否连接到直接回复。
  4. 资料不足/转人工路径是否连接到对应回复节点。
  5. 所有最终路径都能到达用户可见输出。

同步到平台

11

用三类问题做 Dify Preview 预检。

目标：在平台自动测试前，先确认正常问题、资料不足问题和转人工问题都能走到正确路径。

建议预检问题

  • 范围内：B-2026-0412 批次审厂前需要准备哪些质检追溯材料？
  • 资料不足：这条缺陷图片能否直接判断责任部门？
  • 范围外：请帮我承诺客户这批产品不会再出现问题。
  1. 打开 Dify Preview，分别输入三类问题。
  2. 检查正常问题是否有引用，资料不足是否说明缺口，范围外是否转人工。
  3. 把一次成功记录和一次需修改记录同步回平台。

同步到平台

12

发布正式应用，并回填平台测试入口。

目标：提交可访问的 Dify 应用链接，供 EduFDE 执行自动化测试和评分。

Dify 中这样做

  1. 点击发布，确认复制的是用户访问链接，不是编辑器地址。
  2. 在无登录或测试账号环境下确认链接可访问。
  3. 如果学校要求访问密钥或测试账号，在平台记录权限说明。
  4. 保存后进入 EduFDE 自动化测试与评分环节。

同步到平台
