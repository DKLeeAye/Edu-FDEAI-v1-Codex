Automated Evaluation

用平台测试集验证 Dify 智能体是否达到交付门槛。

学生发布 Dify 应用后，需要把链接提交到 EduFDE。平台会围绕正常追溯、证据引用、资料不足和风险边界执行自动化测试，并把失败项定位到 Prompt、知识库、召回、边界分支或节点连线。

本页产物 自动化测试记录 + 评分结果 + 整改清单

通过测试门禁后，学生才能进入阶段五交付说明文档撰写；未通过时，需要回到 Dify 或阶段三对应页面完成整改。

Test Target

测试对象：已发布的 Dify Chatflow 应用。

平台会使用学生回填的发布链接执行测试。这里保留应用、知识库和访问权限记录，便于教师追踪测试对象是否与正式构建记录一致。

Test Suites

平台测试集覆盖四类交付风险。

测试不是只看智能体能否回答，而是看它是否命中证据、引用清楚、知道资料不足，并能把责任判定等风险问题转给人工。

Suite A

正常追溯问题

批次、工序、缺陷、SOP 条款和整改记录是否能被正确检索并组织回答。

Suite B

证据引用问题

回答是否列出来源文件、批次号、标准条款或记录版本，避免只给结论。

Suite C

资料不足问题

缺字段、缺图片标注、缺复检记录时，是否说明资料缺口而不是编造。

Suite D

风险边界问题

责任判定、处罚建议、客户承诺和质量事故归因是否触发转人工。

Run Results

自动化测试结果。

每条结果都会显示期望行为、实际回答摘要、命中证据和问题定位。学生应根据定位回到 Dify 或阶段三进行整改。

等待测试
尚未运行测试

填写或拉取测试对象后，点击“开始自动化测试”。测试结果会在这里展开。

Remediation Loop

整改建议不是泛泛提示，而要指向具体修改位置。

平台根据测试失败类型给出回路：回 Dify 调 Prompt、回知识库处理资料、回 Chatflow 调分支、或回阶段三修改风险边界。

未生成 运行测试后生成整改清单

每个失败项会关联建议动作和回到哪一页 / 哪个 Dify 配置区修改。

Evidence
