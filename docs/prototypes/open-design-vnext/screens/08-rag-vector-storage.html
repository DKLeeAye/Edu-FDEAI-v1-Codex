06 / Vectorization & Storage

向量化与存储：让相似问题能找到相近证据。

本页不真实搭建向量库，而是通过制造业质检样本演示：chunk 如何进入语义空间，元数据为什么必须和向量一起保存。

本页产物 向量存储设计判断

完成语义空间观察、元数据过滤理解和存储策略选择后，进入下一环节的召回策略设计。

Concept

向量化不是“存文本”，而是保存可比较的语义位置。

在质检追溯场景中，学生要理解两件事：语义相近的 chunk 会在向量空间靠近；但真正可交付的系统还必须保存批次、工序、版本、来源等元数据。

Embedding

相似度

元数据

批次号、工序、缺陷类型、来源版本用于过滤范围和保证引用可信。

Storage Model

向量库里不能只存向量，还要存可追溯的业务字段。

如果只保存文本和向量，系统可能找到“语义相近但批次不对”的证据。质检场景必须把元数据作为检索过滤和引用校验的一部分。

存储字段 示例 为什么必须保存
chunk_text “B-2026-0412 批次终检发现外观划伤 3 件...” 供模型生成回答和引用原文。
embedding [0.18, 0.74, ...] 用于计算查询与知识块的语义相似度。
metadata 批次号、工序、缺陷类型、来源版本、责任人 用于过滤、权限隔离、版本控制和审计追溯。
source_ref MES-终检记录-2026-04-12 / 附件 P03 让回答能回到真实证据，不变成“无来源结论”。

Decision Practice

为不同资料选择合适的向量存储策略。

判断时不要只看“能不能向量化”，还要看是否需要元数据过滤、版本隔离和人工复核。

Case A

按批次查询终检异常记录

学生要支持“B-2026-0412 这批终检是否有划伤缺陷？”这种精确追溯问题。

Case B

质检 SOP 每季度会更新版本

同一条检验规则在 2025 版和 2026 版中阈值不同，审厂回答必须引用当前版本。

Case C

缺陷图片只有文件名，没有标注信息

图片文件名为 IMG_8342.jpg，无法知道批次、工序、缺陷类型和拍摄时间。
