09 / Recall Test

召回测试：验证知识库是否真的命中正确证据。

本页训练学生设计测试问题、运行召回结果、判断命中是否可靠，并识别漏召回、误召回和边界问题。

本页产物 召回测试记录

完成测试集设计、结果判断和门禁检查后，进入风险边界说明。

Concept

召回测试不是问一个问题看答案，而是覆盖真实交付中的关键风险。

制造业质检知识库至少要测试范围内问题、字段缺失问题、记录冲突问题和范围外问题。测试结果要回到证据命中情况，而不是只看回答是否顺滑。

01

范围内能命中

批次、工序、缺陷、标准条款等问题应能召回对应记录和来源。

02

证据缺失能识别

资料不足时要提示缺失证据，而不是用相似材料补出结论。

03

范围外能拦截

责任认定、处罚建议和权限外材料应进入人工确认或拒答路径。

Test Bench

构建一组召回测试问题，观察命中结果是否符合预期。

切换测试问题并运行召回，检查 Top-K 结果是否命中目标证据、是否混入相似但错误的材料。

Coverage Matrix

召回测试集要覆盖四类问题，不能只测最容易回答的范围内问题。

学生需要为每类问题判断测试目的、通过标准和失败后要回到哪个前置环节修改。

范围内

已知证据问题

检验知识库能否命中批次记录、SOP 条款、审厂清单等目标证据。

失败后回到：分块 / 向量化 / 召回策略
字段缺失

资料不足问题

检验系统能否发现图片未标注、字段缺失、来源不完整。

失败后回到：数据质量 / 清洗预处理
记录冲突

多证据冲突问题

检验召回结果是否能暴露 MES、Excel、整改记录之间的冲突。

失败后回到：知识结构 / 引用粒度
范围外

越界问题

检验系统是否拒绝责任认定、处罚建议和权限外结论。

失败后回到：风险边界

Decision Practice

判断这些测试失败应回到哪个环节修正。

召回测试的价值在于定位问题来源：是数据质量、分块、向量化、召回策略，还是风险边界没有定义清楚。

Case A

SOP 条款问题只召回整份文件，找不到具体检验条款。

回答引用到了 SOP 文件，但不能定位条款编号和适用工序。

Case B

图片缺陷问题总是命中相似缺陷，但缺少批次和工序。

图片记录已进入知识库，但没有绑定批次号、工序和缺陷位置。

Case C

系统把“是否追责质检员”的问题召回为整改记录并给出建议。

资料可以说明整改事实，但不能支持人员责任判断。
