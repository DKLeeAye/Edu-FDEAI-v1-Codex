## 一、阶段定位

阶段五训练学生将可运行智能体转化为客户可接收、可使用、可维护的交付成果。

本阶段的核心不是“部署命令”，而是交付意识：

- 客户能否访问？
- 客户是否知道怎么用？
- 系统限制是否讲清楚？
- 验收结果是否有记录？
- 后续如何维护和更新？

---

## 二、教学目标

学生完成本阶段后，应能：

- 完成智能体交付说明。
- 完成验收测试记录。
- 说明应用能力边界和已知限制。
- 说明知识库更新和维护方式。
- 面向客户进行演示。
- 在代码路径中完成基础部署和健康检查。

## 四、路径设计

### 4.1 Dify 路径

Dify 路径通常已在云端发布，不要求学生完成完整服务器部署。

但必须完成：

- 应用基本信息
- 功能说明
- 使用说明
- 已知限制
- 知识库维护说明
- Dify 云端依赖说明
- 私有化迁移条件说明
- 客户演示脚本
- 验收记录

### 4.2 LangGraph 代码路径

代码路径需要完成部署训练。

任务：

1. 服务器准备
2. Linux 基础操作
3. Docker 容器化
4. 云服务器部署
5. Nginx 反向代理
6. 自动重启和日志查看
7. 健康检查
8. 验收交付

---

## 五、学生任务流程

通用流程：

```text
整理阶段四成果 → 运行验收测试 → 编写交付文档 → 说明已知限制 → 客户演示 → 提交最终交付包 → 生成项目档案袋和学习画像
```

代码路径额外增加：

```text
容器化 → 服务器部署 → Nginx → 健康检查 → 日志与自动重启
```

## 六、AI 能力参与方式

### 6.1 AI 交付文档评审

评审：

- 功能说明是否清晰
- 限制说明是否诚实
- 维护说明是否可操作
- 是否回应阶段二验收标准

### 6.2 AI 客户验收模拟

模拟客户提出：

- 使用问题
- 范围质疑
- 修改意见
- 运维担忧

学生需要用交付语言回应。

### 6.3 学习画像生成

阶段五完成后触发学习画像生成。

画像必须基于项目档案袋。

---

## 七、质量门禁

阶段五完成条件：

- 应用可访问或交付包可运行。
- 验收测试有记录。
- 交付文档提交。
- 已知限制说明完整。
- 维护说明提交。
- 项目档案袋生成。

代码路径额外要求：

- `/health` 可访问。
- Docker 容器可运行。
- 服务可重启。
- 日志可查看。

## 十一、评分与 Rubric

评分维度：

- 验收测试完成度
- 功能说明清晰度
- 限制说明诚实度
- 维护说明可操作性
- 客户演示表达
- 部署稳定性，代码路径适用
- 项目档案袋完整度

---

## 十二、与前序阶段衔接

阶段五必须回应：

- 阶段二的验收标准
- 阶段四的测试结果
- 阶段四的已知问题
- 阶段三的知识库风险预判

如果阶段四存在未解决问题，阶段五必须在限制说明中披露。

---

## 十三、MVP 范围

MVP 做：

- Dify 路径阶段五
- 部署认知内容
- 交付文档模板
- 验收测试记录
- AI 交付文档评审基础版
- 学习画像基础版

MVP 暂不做：

- 代码路径服务器部署
- 自动触发学生服务器重启测试
- 私有化部署演练
- Nginx/Docker 全流程
- 运维监控面板

---

## 十四、待确认事项

1. Dify 路径是否需要真实调用应用 API 做验收，还是先人工/AI 评审交付文档。
2. 学习画像生成时机是阶段五通过后立即生成，还是教师确认后生成。
3. 阶段五是否要求学生录制客户演示视频。
4. 代码路径部署是否需要平台提供测试云服务器。
5. 交付文档是否支持 PDF 导出。
