## 一、设计定位

实验包是 EduFDE 的核心内容资产。

它不是单纯的配置文件，也不是一组原材料，而是一个可教学、可评估、可授权、可版本化、可共建、可商业化的 AI 智能体项目实训产品。

平台长期护城河来自：

- 高质量行业项目剧本
- AI 客户和评审智能体配置
- 真实感原材料
- 结构化 Rubric
- 标准测试题
- 教师教学材料
- 实验包使用数据与持续迭代

## 二、实验包资产组成

### 2.1 项目剧本资产

项目剧本定义学生面对的真实项目情境。

包含：

- 行业背景
- 企业背景
- 客户角色
- 客户性格
- 表层需求
- 隐藏信息层
- 业务冲突
- 预算约束
- 时间约束
- 数据基础
- 组织阻力
- 真实驱动力
- 项目成功标准

示例：

```text
行业：制造业
场景：汽车零部件质检智能体
客户：生产部门负责人
表层需求：想用 AI 提升质检效率
真实驱动力：明年大客户审厂，需要数字化质检记录
关键约束：预算有限、MES 数据质量差、员工不会用复杂系统
```

### 2.2 训练资源资产

训练资源用于学生学习和操作。

包含：

- 原材料文档
- 问题数据集
- 错误样例
- 优秀样例
- 知识点卡片
- 操作指引
- 案例讲解
- 分块/召回演示素材

### 2.3 评价资产

评价资产用于自动检查、AI 评审和教师评分。

包含：

- 阶段 Rubric
- 检查点
- 红灯规则
- 黄灯规则
- 标准测试题
- 范围外测试题
- 多轮对话测试题
- 参考答案或参考要点
- 教师评分说明

### 2.4 AI 配置资产

AI 配置资产决定平台智能体在该实验包中的行为。

包含：

- AI 客户 Prompt
- AI 客户隐藏信息释放规则
- AI 客户记忆摘要规则
- AI 评审官 Prompt
- AI 导师边界 Prompt
- 学习画像 Prompt
- 模型推荐配置
- Prompt 版本
- AI 行为测试集

### 2.5 交付模板资产

交付模板用于学生产出标准化项目文档。

包含：

- 需求文档模板
- 可行性报告模板
- 总体技术方案模板
- 知识工程决策模板
- 智能体设计说明模板
- 验收报告模板
- 交付文档模板
- 运维说明模板

### 2.6 教师教学资产

教师教学资产用于课程落地。

包含：

- 课程大纲
- 课时建议
- 教学目标
- 课堂讲解重点
- 常见学生错误
- 课堂讨论题
- 课后作业建议
- 评分参考
- 班级复盘模板

## 三、实验包生命周期

实验包生命周期：

```text
立项 → 内容编写 → AI 调试 → 教学评审 → 试点使用 → 正式发布 → 数据复盘 → 新版本
```

### 3.1 立项

确定：

- 行业方向
- 目标课程
- 学生基础
- 项目难度
- 预计课时
- 是否院校共建
- 是否可商业化复用

### 3.2 内容编写

编写：

- 项目剧本
- 原材料
- 阶段任务
- 文档模板
- Rubric
- 教师材料

### 3.3 AI 调试

调试：

- AI 客户角色一致性
- 隐藏信息释放
- AI 评审红黄灯判断
- AI 导师回答边界
- 学习画像生成质量

### 3.4 教学评审

由教研人员或共建教师评审：

- 教学目标是否明确
- 任务难度是否合理
- 产出物是否可评分
- Rubric 是否清晰
- 课程时长是否可控

### 3.5 试点使用

在小范围课程中试点，收集：

- 学生完成率
- 阶段卡点
- AI 客户异常
- AI 评审误判
- 教师反馈
- 实验包难度反馈

### 3.6 正式发布

发布后可授权给院校课程使用。

正式发布版本必须锁定：

- 实验包版本
- 阶段配置
- Rubric
- Prompt 版本
- 标准测试题
- 原材料版本

### 3.7 数据复盘与新版本

基于使用数据迭代：

- 调整材料
- 调整 AI 客户
- 调整评分规则
- 增加教师说明
- 发布新版本

历史课程继续绑定旧版本。

## 四、版本管理

### 4.1 版本原则

- 课程创建时绑定具体实验包版本。
- 学生实验会话继承课程绑定版本。
- 新版本不影响历史课程。
- 已发布版本原则上不可直接修改关键内容。
- 修改关键内容必须发布新版本。

### 4.2 版本号规则

建议使用：

```text
主版本.次版本.修订版本
```

示例：

- `1.0.0`：首次正式发布
- `1.1.0`：新增阶段任务或评分规则调整
- `1.1.1`：修正文案、错别字、非关键材料说明

### 4.3 版本变更类型

| 类型 | 是否影响历史课程 | 是否需要新版本 |
|---|---:|---:|
| 文案错别字 | 否 | 可选 |
| 教师说明补充 | 否 | 可选 |
| 原材料替换 | 是 | 是 |
| AI 客户隐藏信息调整 | 是 | 是 |
| Rubric 权重调整 | 是 | 是 |
| 标准测试题调整 | 是 | 是 |
| 阶段任务结构调整 | 是 | 是 |

## 五、质量门禁

实验包发布前必须通过质量门禁。

### 5.1 内容完整性检查

检查：

- 五阶段任务是否完整
- 原材料是否齐全
- 每阶段输出物是否明确
- 教师材料是否齐全
- Rubric 是否覆盖关键能力

### 5.2 AI 行为测试

检查：

- AI 客户不主动泄露隐藏信息
- AI 客户角色一致
- AI 客户能自然结束对话
- AI 评审能识别红灯问题
- AI 评审能区分黄灯风险
- AI 导师不直接给答案

### 5.3 验收测试题检查

检查：

- 标准范围内问题可回答
- 范围外问题应拒答
- 多轮指代问题可处理
- 关键知识点被覆盖

### 5.4 教学可用性检查

检查：

- 预计课时是否合理
- 难度是否匹配目标学生
- 教师能否理解评分标准
- 学生是否能独立推进

## 六、授权与派生

### 6.1 标准实验包

由平台创建和维护，可授权给多个院校使用。

### 6.2 院校定制包

从标准包派生，包含院校定制内容。

规则：

- 不直接修改标准包。
- 定制包有独立版本。
- 授权范围按合同约定。
- 可选择是否允许平台复用。

### 6.3 共建实验包

由平台与院校或教师共同创建。

必须明确：

- 版权归属
- 署名规则
- 发布范围
- 收益分成
- 是否可进入平台实验包市场

## 七、建议数据模型

### 7.1 核心实体

```text
experiment_packages
  实验包主实体

experiment_package_versions
  实验包版本

stage_blueprints
  阶段蓝图

package_assets
  原材料、模板、教师材料等资产

rubrics
  评分规则

rubric_items
  评分项

ai_personas
  AI 客户、评审官、导师等人设配置

prompt_versions
  Prompt 版本

acceptance_tests
  标准验收测试题

package_derivations
  标准包与定制包派生关系

content_entitlements
  租户或院校的内容权益
```

### 7.2 课程绑定

课程必须绑定 `package_version_id`，而不是只绑定实验包主实体。

```text
course → experiment_package_version
session → course → experiment_package_version
```

## 八、制造业质检 AI 实验包 v1 示例结构

### 8.1 项目剧本

- 行业：制造业
- 企业：中型汽车零部件工厂
- 客户：生产部门负责人
- 表层需求：提升质检效率
- 真实驱动力：大客户审厂要求质检记录数字化
- 关键约束：预算有限、MES 数据质量差、员工不愿用复杂系统

### 8.2 阶段产出

| 阶段 | 输出物 |
|---|---|
| 需求访谈与问题发现 | 访谈记录、需求假设、未确认问题 |
| 方案定义与可行性判断 | 需求文档、可行性报告、总体技术方案 |
| 知识工程决策 | 知识工程决策文档、风险预判 |
| 智能体实现与测试 | Dify 智能体、设计说明、测试结果 |
| 交付验收与运维说明 | 交付文档、验收记录、维护说明 |

### 8.3 标准测试题

示例：

- 范围内：质检漏检率如何统计？
- 范围内：不合格零件处理流程是什么？
- 范围内：质检记录数字化需要保存哪些信息？
- 范围外：今天股市行情怎么样？
- 多轮：刚才说的第一步具体怎么做？

## 九、MVP 范围

MVP 阶段：

- 仅内置一个制造业质检 AI 实验包。
- 实验包由平台初始化脚本写入。
- 暂不开发完整实验包创作工作台。
- 必须保留实验包版本概念。
- 必须保留 Rubric 和标准测试题结构。
- 必须保留 AI Persona 与 Prompt 版本字段。

## 十、待确认事项

1. 实验包版本发布后是否允许修正非关键文案，还是全部通过新版本处理。
2. 共建实验包的版权协议模板需要单独设计。
3. 实验包质量门禁是否在 v1 做自动化，还是先由平台教研人工检查。
4. 教师是否能在 v1 创建私有实验包草稿。
5. 实验包市场是否进入 v2，还是后置到 v2.5。
