# EduFDE Codex 开发指南

> 每个 Codex 开发会话都应优先阅读本文件。本文只保存工程级上下文，详细产品和技术方案以 `docs/*v2.0.md` 为准。

## 一、项目定位

EduFDE 是面向高校的 **AI 智能体项目交付实训平台**。

平台训练学生完成完整 AI 智能体项目交付链路：

```text
需求访谈与问题发现
→ 方案定义与可行性判断
→ 知识工程决策
→ 智能体实现与测试
→ 交付验收与运维说明
```

当前项目已完成 **MVP 本地演示闭环与收口审查**，并已完成正式学生端 UI 静态原型确认、前端产品 UI 设计规格沉淀、正式学生端产品 UI 第一轮收口和硅基流动真实 LLM Provider 接入。项目已经进入 **产品化精修与真实能力迭代阶段**：后续不再以“把页面和接口快速铺满”为主，而是逐页打磨学生端真实教学体验，同时同步补强后端规范、AI 行为、Artifact 结构和长期架构边界。当前精修主线已进入阶段一；教学引导模式第一轮功能体验已阶段性收口，具备六关卡连续访谈、训练记录隔离、真实 AI 客户、客户行为守卫和消息体验优化。下一步重点切换为阶段一项目实战模式，打磨正式客户拜访、拜访间整理、问题发现总结、综合评估和阶段二输入证据链。

## 三、当前开发目标

在不破坏终局架构地基的前提下，把已验证的 MVP 能力产品化。

MVP 已完成验证：

- 一个制造业质检 AI 智能体实验包
- 学生端完整五阶段流程
- 阶段一 AI 客户
- 阶段二 AI 评审
- 阶段三知识工程决策工具
- 阶段四 Dify 路径
- 阶段五 Dify 交付文档
- 基础教师进度视图
- 基础学习画像

后续迭代必须继续保留这些结构性地基：

- 实验包版本绑定
- 统一 Artifact 模型
- AI Gateway 边界
- 租户 / 院校 / 课程作用域
- 项目档案袋雏形
- AI 调用日志
- 黄灯债务最小模型
- Rubric 最小模型

## 四、计划技术栈

前端：

- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui
- React Query
- Zustand

后端：

- FastAPI
- Python 3.11+
- SQLAlchemy 2.x
- Alembic
- Pydantic v2
- PostgreSQL
- Redis
- MinIO/S3 兼容对象存储
- Celery

AI：

- 所有模型调用必须经过 AI Gateway
- 需要时使用 LangGraph 构建平台智能体
- MVP 阶段 AI 流式输出优先使用 SSE

## 五、架构原则

1. 所有 AI 调用必须经过 AI Gateway，阶段服务不得直接调用模型供应商。
2. 课程必须绑定实验包版本，而不是只绑定实验包主 ID。
3. 阶段输出必须保存为 Artifact。
4. AI 评审必须绑定 Rubric 和证据。
5. 教师拥有最终教学判断权。
6. 服务层查询必须强制执行租户 / 院校 / 课程作用域。
7. MVP 可以简化 UI 和流程，但不能删除长期架构边界。

## 六、推荐会话流程

每次新开发会话开始时：

1. 阅读本文件。
2. 阅读 `docs/README.md`。
3. 阅读 `docs/dev/progress.md`。
4. 阅读 `docs/dev/decisions.md`。
5. 阅读本次任务相关的 v2.0 设计文档。
6. 在编辑前确认任务边界。

开发过程中：

1. 每个会话只处理一个边界清晰的模块。
2. 后端和前端尽量按可独立验证的切片推进。
3. 保持改动范围收敛。
4. 对有意义的行为添加或更新测试。
5. 在宣称完成前运行验证命令。
6. 涉及前端体验时，尽量启动开发服务并在浏览器验证。

每次会话结束时：

1. 更新 `docs/dev/progress.md`。
2. 如果产生长期产品或技术决策，更新 `docs/dev/decisions.md`。
3. 在最终回复中按 `docs/dev/session-handoff-template.md` 说明交接信息，或按需创建日期化交接记录。
4. 明确说明已完成的验证和未验证区域。

## 七、MVP 推荐开发顺序

已完成：

1. 项目脚手架
2. 数据库与基础模型
3. 认证与用户 / session 基础
4. 实验包初始化
5. 课程 / session / stage 状态
6. AI Gateway
7. Artifact 模型
8. 阶段一至阶段五最小闭环
9. 教师进度视图
10. 基础学习画像
11. MVP 收口审查与演示准备
12. 正式学生端 UI 静态原型与设计规格

下一阶段推荐顺序：

1. 学生端产品化精修：从登录页、课程列表、实验项目主页到阶段一至阶段五逐页打磨，减少同质化输入框，恢复每个阶段独有的任务形态和教学体验；当前优先推进阶段一项目实战模式。
2. 阶段一项目实战模式功能打磨：正式客户拜访、多轮访谈上下文、客户角色稳定性、访谈线索沉淀、待追问问题、拜访间整理、问题发现总结、综合评估和阶段二输入证据链。
3. 阶段一教学引导模式回归维护：六关卡训练记录继续隔离，不写正式 Artifact，不作为阶段二输入；后续仅处理阻塞性缺陷和必要体验回归。
4. 阶段二至阶段五真实 AI 评审逐步替换 fake 风格输出，并补齐结构化 Prompt、Rubric 证据绑定和错误处理。
5. 真实 Dify API 集成、黄灯债务可视化、学习画像智能化等真实能力增强。
6. 正式教师后台 UI、课程成员模型替换 `created_by_user_id` 临时权限边界、教师批改与正式评分。
