# 阶段一 UI 精修基线

> 确认日期：2026-05-07  
> 原型文件：`docs/prototypes/stage-one-desktop-layout-v3-collapsed-global-sidebar.html`

## 一、信息架构决策

阶段一采用“教学引导模式”和“项目实战模式”分离的信息架构。

- 教学引导模式用于训练访谈能力，推荐首次学习先完成，但不强制阻塞项目实战。
- 项目实战模式用于正式客户拜访，并承担进入阶段二前的正式证据链。
- 阶段二的正式输入只来自项目实战模式，不读取教学引导练习内容，避免训练记录污染正式项目交付证据。

## 二、阶段内全局导航规则

学生进入五阶段实验工作区后，EduFDE 全局侧边栏保持收起为窄栏的状态。

阶段内页面只保留：

- 收起的 EduFDE 全局窄侧栏。
- 顶部返回 / 刷新等轻量操作入口。
- 五阶段导航或当前阶段内导航。
- 中央任务工作区。
- 与当前任务强相关的右侧上下文栏。

课程列表页和实验课程总览页仍可使用完整 EduFDE 全局侧边栏；阶段一至阶段五工作区使用全局窄侧栏，减少横向占用。

## 三、阶段一主页

阶段一主页是独立页面，用于模式选择和进度总览。

页面应包含：

- 阶段一标题和任务说明。
- 教学引导模式入口。
- 项目实战模式入口。
- 阶段一进度总览：教学引导、项目实战拜访、拜访间整理、问题发现总结、综合评估。
- 五阶段交付主线导航，样式和现有课程实验进入后的工作区左侧导航保持一致：白色卡片、标题为“五阶段交付主线”、当前阶段深色高亮、已完成阶段使用完成色、锁定阶段显示锁定态。

## 四、教学引导模式页面

教学引导模式是独立对话训练页，核心仍是客户对话窗口。

布局结构：

- 左侧：六关卡进度，包括建立信任、摸清业务现状、定位核心痛点、澄清期望与约束、数据与可行性探测、总结确认与推进。
- 中央：对话窗口。窗口顶部展示客户身份介绍，例如车间主任、厂长、质检主管等。
- 右侧：当前关卡目标、提问技巧、推荐问句和 AI 反馈区。
- 底部：学生输入框和发送按钮。

进入教学引导模式后使用专注任务布局，不显示阶段一主页的五阶段交付主线，也不显示通用阶段上下文栏。页面主体严格保持“六关卡进度 / 对话窗口 / 本关目标与提问辅助”三栏结构。

教学引导模式下 AI 客户可以适度配合，但不能直接给标准答案。页面侧重点是训练学生提问能力和反馈当前关卡表现。

当前实现状态：

- 页面初版已落地到正式学生端阶段一工作区。
- 桌面横屏下已实现左侧六关卡进度、中间客户对话、右侧本关目标与提问辅助的三栏布局。
- 页面已从阶段一主页的五阶段交付主线和通用右侧上下文栏中拆出，进入教学引导模式后保持专注任务布局。
- 当前仍属于页面和功能精细化打磨阶段，训练功能还不是最终状态。

下一步功能打磨重点：

- 六关卡状态：明确当前关、已完成关、可重试关和未开始关的推进规则。
- 对话体验：让学生追问、客户回应、历史上下文和输入框形成稳定训练闭环。
- 提问辅助：推荐问句应能一键填入或改写，同时避免让学生只机械点击答案。
- AI 分析：从静态提示升级为基于当前学生提问的反馈，覆盖开放性、聚焦度、证据意识和追问深度。
- 重试 / 继续：每关需要支持重试、完成本关、进入下一关，且反馈要说明为什么可以继续或需要重试。
- 训练记录边界：可记录教学训练进度和反馈，但不写入项目实战正式证据，不作为阶段二正式输入。

## 五、项目实战模式页面

项目实战模式是独立正式客户拜访页，核心同样是客户对话窗口。

布局结构：

- 中央：正式客户对话窗口。窗口顶部展示客户身份、业务背景和角色边界。
- 右侧：客户身份提示、实时访谈线索、待追问问题和正式产出流程。
- 底部：学生输入框和发送按钮。

项目实战模式不展示教学关卡技巧，以免削弱真实拜访感。右侧应强调“已触及线索 / 待追问信息 / 正式产出进度”。

## 六、正式产出链路

项目实战模式后的正式链路为：

```text
客户拜访
→ 拜访间整理
→ 问题发现总结
→ 阶段一综合评估
→ 解锁阶段二
```

拜访间整理、问题发现总结和阶段一综合评估属于项目实战模式的正式交付链路，不属于教学引导模式的正式输出。
