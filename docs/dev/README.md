# EduFDE 开发治理说明

本目录用于保存长期开发上下文，避免依赖单个聊天会话记忆。

目标是让每个 Codex 会话都能短、准、可恢复。

## 一、文件说明

- `progress.md`  
  记录当前实现状态、已完成模块、验证结果和下一步建议任务。

- `decisions.md`  
  记录长期有效的产品和工程决策。凡是会影响后续开发的选择，都应写入这里。

- `session-handoff-template.md`  
  用于结束一个开发会话时做交接，降低下一个会话的上下文成本。

- `module-prompt-template.md`  
  用于启动具体模块开发会话的提示词模板。

## 二、会话纪律

每个开发会话只处理一个边界清晰的目标。

合适的会话范围：

- 初始化后端应用和 Docker Compose。
- 实现 AI Gateway 模块。
- 实现阶段一后端 API。
- 实现阶段一学生端界面。

不合适的会话范围：

- 一次性构建整个 MVP。
- 一次性实现全部五个阶段。
- 在添加功能时顺手大规模重构无关模块。

## 三、新会话必须阅读的上下文

每个开发会话开始时，应让 Codex 阅读：

1. `AGENTS.md`
2. `docs/README.md`
3. `docs/dev/progress.md`
4. `docs/dev/decisions.md`
5. 本次任务相关的 v2.0 设计文档

## 四、每个会话的结束要求

每个实现会话结束时，应明确：

- 修改了哪些文件
- 做了哪些验证
- 有哪些未验证区域
- 是否更新了 `progress.md`
- 是否需要更新 `decisions.md`
- 下一步推荐任务是什么
