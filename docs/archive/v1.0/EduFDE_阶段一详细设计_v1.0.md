## 一、阶段定位

### 教学目标

让没有任何工作经验的学生，从"完全不知道说什么"逐步成长为"能够系统性挖掘客户需求"的售前人员。

核心要传递的三个认知：

1. **假设驱动**：优秀的需求挖掘不是被动问答，而是带着自己的业务框架假设去验证和修正
2. **信息解码**：客户说出来的不是他真正要的，表面需求背后有更深的痛点和约束
3. **多轮迭代**：真实项目不是谈一次就结束，每次对话都是在上一次基础上的深化

### 阶段在整体流程中的位置

```
[阶段一：售前需求挖掘] → 阶段二：需求拆解分析 → ... → 阶段五：部署交付
        ↑
    本文档范围
```

阶段一的最终输出物将直接作为阶段二的输入。

## 二、双模式设计

阶段一提供两种完全不同的学习路径，学生可自由选择，但推荐先完成教学过关模式。

```
┌─────────────────────────────────────────────────────────┐
│                    阶段一：售前需求挖掘                    │
├──────────────────────────┬──────────────────────────────┤
│      教学过关模式          │        实战模拟模式            │
│                          │                              │
│  六个递进关卡             │  完整连续的客户拜访            │
│  每关聚焦一个核心能力      │  无任何引导和提示              │
│  关卡内可反复重试          │  支持多轮次拜访               │
│  即时AI反馈               │  结束后综合评估报告            │
│                          │                              │
│  适合：零基础入门          │  适合：检验和强化学习成果       │
└──────────────────────────┴──────────────────────────────┘
```

**进入实战模拟模式的提示：**
- 未完成教学模式时进入，系统给出建议提示（不强制拦截）
- 完成教学模式后，实战模式入口高亮解锁

## 三、教学过关模式

### 3.1 六关卡结构

六个关卡覆盖一次完整需求挖掘的全部核心能力，难度递进：

| 关卡 | 名称 | 核心能力 | 对话目标 |
|------|------|---------|---------|
| 关卡一 | 建立信任与破冰 | 开场控场 | 让客户从防御变为愿意聊 |
| 关卡二 | 摸清业务现状 | 假设驱动提问 | 能复述客户的业务流程，客户确认准确 |
| 关卡三 | 定位核心痛点 | 从现象到本质 | 挖出至少3个具体痛点，追问到根本原因 |
| 关卡四 | 澄清期望与约束 | 边界探测 | 摸清期望、预算、时间、内部资源 |
| 关卡五 | 数据与可行性探测 | AI项目前提判断 | 摸清数据现状，判断可行性等级 |
| 关卡六 | 总结确认与推进 | 结构化收尾 | 口头总结获客户确认，约定下一步 |

### 3.2 单个关卡内部流程

每个关卡的体验结构固定，学生清楚知道自己在哪个环节：

```
┌──────────────────────────────────────────────────┐
│  关卡 N：[关卡名称]                                │
├──────────────────────────────────────────────────┤
│                                                  │
│  STEP 1：知识热身  ────────────────  约3-5分钟    │
│  · 1-2个核心概念卡片（可翻转查看详情）             │
│  · 1个真实场景的文字案例片段                       │
│  · 1道思考题（不评分，激活思维用）                 │
│                                                  │
│  STEP 2：目标说明  ────────────────  约1分钟      │
│  · 明确告知：这一关只需要做到一件事                │
│  · 给出"好的表现"和"不好的表现"对比示例（文字）   │
│                                                  │
│  STEP 3：对话练习  ────────────────  无时间限制   │
│  · 进入与AI客户的对话界面                         │
│  · 左侧始终显示本关卡目标（不消失）                │
│  · 可以随时重新开始本关卡对话                      │
│  · 没有提示系统，靠学生自己想                      │
│                                                  │
│  STEP 4：关卡AI分析  ──────────────  自动生成     │
│  · 你做到了什么（具体引用对话片段）                │
│  · 你没做到什么（具体指出遗漏）                    │
│  · 一个最值得改进的具体建议                        │
│  · 操作选项：[重试本关] [继续下一关]               │
│                                                  │
└──────────────────────────────────────────────────┘
```

**关键设计原则：**
- 每关对话只考察该关的目标，AI客户在教学模式下配合度更高
- 教学模式下AI客户没有跨关卡的记忆（每关是独立的对话）
- 不设提示系统，避免依赖；靠关卡前的目标说明给足方向感

## 四、实战模拟模式

### 4.1 基本设定

- 完整连续的客户拜访，无任何关卡分割
- 无引导提示，AI客户按真实人物设定行事
- 支持针对同一场景反复挑战（每次是独立的新对话）
- 结束后生成综合评估报告

### 4.2 多轮拜访机制

不同难度的实验场景，预设不同的拜访轮次：

| 场景难度 | 拜访轮次 | 说明 |
|---------|---------|------|
| 入门级 | 1次 | 一次对话完成全部信息挖掘 |
| 标准级 | 2次 | AI客户第一次会在适当时机主动结束对话 |
| 进阶级 | 3次 | 三次拜访，信息逐步释放，复杂度更高 |

**AI客户自然结束对话的设计：**

客户不会突然中断，而是用真实场景下会出现的自然话语结束：

> "行了，你先把我们今天聊的整理一下，我这边还有个会，你下次来的时候带个初步方案，我们再详细谈。"

这句话出现的时机由 AI 客户根据对话进展判断，而非固定在第N句话。

### 4.3 拜访间整理环节（多轮拜访专属）

当AI客户结束第一次对话后，学生进入整理环节，这是两次拜访之间的必经步骤：

```
┌─────────────────────────────────────────────────────┐
│  第一次拜访结束 — 整理你的收获                         │
│  提交后才能进行第二次拜访                              │
├─────────────────────────────────────────────────────┤
│                                                     │
│  1. 已确认的信息                                     │
│     客户背景：___________________________________    │
│     业务现状：___________________________________    │
│     核心痛点：___________________________________    │
│                                                     │
│  2. 我的初步判断                                     │
│     客户最核心的需求是：_________________________    │
│     我认为AI可以解决的是：_______________________    │
│     我认为存在的风险是：_________________________    │
│                                                     │
│  3. 下次拜访计划                                     │
│     还需要确认的信息：___________________________    │
│     我准备重点问的问题：_________________________    │
│                                                     │
│  4. 初步方案摘要（提交给客户看的）                    │
│     [较大的文本输入框]                               │
│                                                     │
│                          [提交，开始第二次拜访]      │
└─────────────────────────────────────────────────────┘
```

**整理环节的评估：**
整理内容被 AI 静默评估，结果暂不展示给学生，记入最终报告。评估维度：
- 信息整理的准确性（对比AI客户的真实设定）
- 初步判断的合理性
- 下次拜访计划的针对性

### 4.4 多轮记忆机制（B+C组合方案）

**第二次拜访的AI客户上下文构成：**

```
① 客户基础人设（固定不变）

② 客户记忆摘要（由第一次对话结束时自动生成）
   格式：
   - 这个学生了解到的信息：[内容]
   - 他没有问到的：[内容]
   - 我对他的整体印象：[敷衍 / 还行 / 专业]
   - 我上次承诺他的：[内容]
   - 我还没透露的重要信息：[内容]

③ 学生提交的整理文档
   客户基于此形成预设态度：
   - 理解准确的部分 → 客户认可，但不主动补充
   - 理解有偏差的部分 → 客户用自己的方式纠正，不直接说"你错了"
   - 完全遗漏的重要信息 → 客户不主动提，除非学生在对话中触碰到
   - 整体印象（由整理质量决定）→ 影响客户本次的配合程度

④ 本轮拜访的隐藏信息层（预设本次可以释放哪些新信息）
```

**学生侧（界面左侧显示）：**
- 自己上次填写的整理表单内容（作为提醒，不进入对话上下文）

**核心设计原则：信息不对称**
客户知道自己的完整背景和学生的整理内容，学生只知道自己整理出来的内容。这种不对称是真实售前的核心张力，也是教学价值所在。

**客户印象影响对话难度：**
- 第一次挖掘浅 → 客户印象差 → 第二次态度敷衍，信息更难挖
- 第一次挖掘好 → 客户印象好 → 第二次更愿意深聊，甚至主动提供信息

## 五、AI客户角色设计规范

### 5.1 角色设定要素

每个实验场景的AI客户必须包含以下设定层：

```yaml
基础信息:
  姓名: 张厂长
  年龄: 48
  职位: 生产部门负责人
  性格: 务实、对技术半懂不懂、预算敏感

表层信息（主动会说的）:
  - 工厂有质检问题
  - 人工漏检率大概10%
  - 想用AI解决一些问题

隐藏信息层1（被问到才说）:
  - 现有一套老旧MES系统
  - 质检员流动率高，培训成本大

隐藏信息层2（深度追问才说）:
  - MES系统数据质量很差
  - 真实预算只有20万

隐藏信息层3（几乎不会主动说，需要极好的引导）:
  - 明年有大客户审厂，质检记录需要数字化
  - 这才是最核心的真实驱动力

防御性设定:
  - 预算话题：先回避，被追问会说"你们先报方案"
  - 技术细节：不懂装懂，会用模糊语言带过
  - 对AI的态度：见过失败的IT项目，有戒心

对话风格:
  - 说话直接，不喜欢绕弯子
  - 经常用"这个能落地吗"、"别给我整虚的"
  - 时间观念强，会表现出不耐烦
```

### 5.2 AI客户行为规范

AI客户在对话中必须遵守的原则：

**永远不做的事：**
- 不主动说出隐藏信息层的内容
- 不直接回答"你们需要多少预算"之类的直白提问
- 不对学生的方向给出明确肯定（真实客户不会这样）

**应该做的事：**
- 根据学生问题质量决定信息释放深度
- 问题太浅 → 给模糊答案
- 问题触到痛点 → 会有情绪反应，话变多
- 保持角色一致性，不因为学生"绕回去问"就重置态度

### 5.3 教学模式 vs 实战模式的客户行为差异

| 行为维度 | 教学模式 | 实战模式 |
|---------|---------|---------|
| 配合程度 | 较高，适当引导学生 | 真实难度，不主动帮 |
| 信息释放 | 稍微主动一些 | 严格按隐藏层设定 |
| 对话结束 | 关卡目标达成即结束 | 自然结束，时机由AI判断 |
| 角色扮演 | 允许轻微出戏提示 | 严格保持角色 |

## 六、评估体系

### 6.1 关卡级评估（教学模式）

每个关卡结束后即时生成，聚焦本关目标：

```
关卡N 评估报告

✅ 你做到了
   · [具体引用对话片段，说明做得好的地方]

❌ 你没做到
   · [具体指出遗漏或失误]

💡 最值得改进的一点
   · [一条具体、可操作的建议]
```

### 6.2 实战模拟综合评估报告

一次完整实战结束后生成：

```
本次需求挖掘综合评估

【信息覆盖雷达图】
  现状摸底     ████████░░  80%
  痛点定位     █████░░░░░  50%
  期望澄清     ███████░░░  70%
  约束探测     ████░░░░░░  40%
  数据摸底     ██░░░░░░░░  20%
  总结对齐     █████████░  90%

【对话质量评分】
  提问深度     72分
  信息完整度   58分
  沟通节奏     85分
  总结能力     41分
  综合得分     64分

【关键发现】
  你成功挖掘出了：XXX、XXX、XXX
  你完全遗漏了：XXX（这是本场景最关键的隐藏信息）
  最值得注意的对话时刻：
  [引用具体对话片段，说明为什么这个时刻很关键]

【整理环节评估】（多轮拜访专属）
  信息准确性：你整理的内容中，XX%与客户真实情况吻合
  判断合理性：你对核心需求的判断[准确/有偏差，偏差在...]
  计划针对性：你的下次拜访计划[有针对性/过于宽泛]

【与上次实战对比】（非首次时显示）
  综合得分变化：+X分
  进步最明显的维度：XXX
  仍需加强的维度：XXX
```

### 6.3 评估后台评分框架

AI评估基于以下六个维度，对学生不可见（只展示结果不展示框架）：

```
① 现状摸底   — 是否澄清了客户业务流程和现有系统情况
② 痛点定位   — 是否挖到具体痛点，是否追问到根本原因
③ 期望澄清   — 是否了解理想状态和验收标准
④ 约束探测   — 预算/时间/人员/组织阻力，覆盖情况
⑤ 数据摸底   — 数据来源/质量/系统情况，AI可行性判断
⑥ 总结对齐   — 结尾是否有结构化总结，是否推进了下一步
```

## 七、阶段一输出物

学生完成阶段一后，产出以下内容，作为阶段二的输入：

### 7.1 需求访谈记录（系统自动整合）

```
项目场景：[场景名称]
完成时间：[时间]
拜访轮次：[N次]

已确认信息汇总：
  客户背景：[来自学生整理 + AI补全遗漏标注]
  业务现状：[...]
  核心痛点：[...]
  期望与约束：[...]
  数据情况：[...]

信息完整度评级：[完整 / 基本完整 / 有明显遗漏]
  遗漏项提示：[如有遗漏，标注出来，但不给答案]

阶段一综合得分：[X分]
```

### 7.2 进入阶段二的条件

- 实战模拟至少完成一次（不设分数门槛，但遗漏项会影响阶段二难度）
- 多轮拜访场景需完成全部轮次
- 整理环节需提交（多轮拜访场景）

## 八、界面设计要点

### 8.1 整体布局

```
┌─────────────────────────────────────────────────────────┐
│  顶部：阶段进度 | 当前模式 | 关卡进度（教学模式）          │
├──────────────────┬──────────────────────────────────────┤
│                  │                                      │
│  左侧引导面板     │         右侧：对话工作区               │
│                  │                                      │
│  教学模式显示：   │  · 对话消息流（气泡样式）              │
│  · 当前关卡目标  │  · 客户头像+姓名+职位                  │
│  · 关卡进度      │  · 输入框（支持打字）                  │
│                  │  · 发送按钮                           │
│  实战模式显示：   │                                      │
│  · 客户背景简介  │  整理环节显示：                       │
│  · 上次整理内容  │  · 结构化表单                         │
│  （第二次起）    │  · 提交按钮                           │
│                  │                                      │
├──────────────────┴──────────────────────────────────────┤
│  底部：AI助手（仅教学模式可用）| 结束本次对话              │
└─────────────────────────────────────────────────────────┘
```

### 8.2 对话交互方式

- **主要方式：打字输入**（文本对话，主流且易于评估）
- **后续迭代可考虑：语音输入**（更接近真实场景，但评估复杂度高，暂不列入MVP）

### 8.3 关键交互细节

- AI客户回复有打字动画效果（模拟真实对话节奏感）
- 学生可以查看当前对话的完整历史记录
- 教学模式下，关卡目标卡片始终固定在左侧，不随滚动消失
- 整理环节支持草稿自动保存（防止意外丢失）

## 九、待确认事项

> 阶段一设计已达成共识，以下为开发阶段需进一步细化的技术决策

1. **语音输入**：MVP阶段仅支持文字，语音列入v1.2迭代
2. **AI客户的Prompt工程**：具体的system prompt模板需要在开发阶段打磨测试
3. **评分权重**：六个评估维度的具体权重需要结合第一个场景测试后调整
4. **整理环节的表单字段**：当前为通用设计，不同场景可能需要定制字段
