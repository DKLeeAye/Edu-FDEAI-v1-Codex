## 一、阶段定位

### 教学目标

让学生理解知识库构建的完整知识体系，做出有依据的配置决策，核心是训练三个递进能力：

1. **数据审视能力**：理解数据质量问题的类型和识别方法，知道什么样的数据会导致什么样的知识库问题
2. **策略判断能力**：理解不同分块和召回策略的适用场景，基于项目实际情况做出有依据的策略选择
3. **迭代诊断能力**：理解知识库三类常见问题的诊断逻辑，能够在阶段四执行时发现并定位问题

> **定位说明（v1.1更新）：**
> 阶段三是**决策层**，不是执行层。学生在平台上完成所有的策略理解、配置选择、效果认知，输出知识库配置决策文档。知识库的真实构建在阶段四中完成（Dify路径在Dify中构建，代码路径用LangGraph构建）。
> 平台的目的是让学生学习到知识并独立思考和选择，而不是要求学生在本阶段做出生产级的知识库。

### 核心设计原则

**深入浅出，永远为想深入的学生留一扇门：**
每个概念的呈现以理解为目标，通过可视化工具建立直觉，每个配置项旁边有"查看原理"展开按钮，感兴趣的学生可以深入了解背后的技术逻辑。这个原则贯穿整个阶段三。

### 阶段在整体流程中的位置

```
阶段二输出（技术架构文档中的知识库方案选择）
         ↓
   【阶段三：知识库决策】← 本文档范围
         ↓
   阶段四：智能体开发
   （学生带着阶段三的决策文档，在Dify或LangGraph中真实构建知识库）
```

### 阶段三与阶段二的联动

- 阶段二技术架构文档中的知识库方案选择，作为阶段三的学习起点和决策参考
- 阶段二的黄灯债务（如数据质量风险未充分评估），在阶段三入口提示：
  > "你在可行性报告中提到了数据质量风险，在学习知识库数据准备时请重点关注数据质量问题的识别"

### 阶段三与阶段四的联动

- 阶段三输出的**知识库配置决策文档**直接指导阶段四的知识库构建
- 阶段三的学习质量决定了阶段四构建时的判断能力——理解越深，执行时越少走弯路

## 二、知识体系五层结构

阶段三涵盖知识库构建的完整知识体系，五层递进：

```
第一层：数据准备          ← 地基，决定知识库质量上限
第二层：分块策略          ← 决定信息的组织方式
第三层：向量化与存储      ← 幕后基础设施
第四层：召回策略          ← 决定如何找到答案
第五层：效果评估与迭代    ← 持续优化闭环
```

每一层的学习都包含**预置案例教学**和**决策练习**两个环节，顺序固定：先通过案例建立认知，再针对自己的项目做出有依据的配置选择，输出决策文档。

## 三、第一层：数据准备

### 教学目标

让学生理解数据质量问题不是技术问题，是认知问题——学会用挑剔的眼光审视原始数据，在进入系统之前发现并解决问题。

> 核心认知：垃圾进垃圾出，这一层做不好，后面所有精细调优都是白费。

### 知识内容

**数据收集与盘点：**
- 数据来源类型（文档、数据库、网页、图片等）及各自的处理难点
- 如何建立数据清单：有什么、在哪里、谁负责、质量如何

**数据质量问题识别（四类）：**

| 问题类型 | 具体表现 | 典型示例 |
|---------|---------|---------|
| 格式问题 | 乱码、特殊字符、PDF转换残留符号 | `零件漏检率为1O%`（O被识别为字母） |
| 内容问题 | 重复内容、过期信息、矛盾信息 | 同一份规范出现新旧两个版本 |
| 结构问题 | 表格、图片、页眉页脚、水印干扰 | 每页页眉"XX公司内部文件"混入正文 |
| 完整性问题 | 关键信息缺失、文档残缺 | 操作规范第3章内容为空 |

**数据清洗操作：**
- 格式标准化
- 去重处理
- 无效内容过滤
- 清洗后的质量验证

### 教学方式：问题数据集识别练习

平台预置一批刻意设计了各类质量问题的原始数据，学生的任务是识别出所有问题类型并说明处理思路——**不是真正执行清洗**，而是建立"看到这类数据要想到这类问题"的认知习惯：

```
任务说明：
以下是制造业质检项目的原始数据包，
共包含15份文档，其中存在若干质量问题。
请找出所有问题，说明问题类型，并描述处理思路。

[开始检查]

完成后：
你识别出了 8 个问题，共有 11 个问题
遗漏的问题：
  · 第3份文档存在新旧版本重复（内容问题）
  · 第7份文档页眉内容未过滤（结构问题）
  · 第12份文档第4页存在乱码（格式问题）
```

"找茬游戏"的逻辑——把抽象的数据质量认知变成有目标感的识别任务。

### 决策输出：数据准备决策项

完成识别练习后，学生针对自己项目的原材料填写决策项：

```
数据准备决策

原材料概况：
  文档数量：___份  主要格式：___  预计总字数：___

识别到的质量风险：
  · [描述发现的或预判的质量问题]

清洗策略选择：
  ☑ 移除页眉页脚     ☑ 过滤特殊字符
  ☑ PDF排版符号清理  ☑ 重复段落去重
  ☐ 其他：___

选择依据：
  [说明为什么选择以上清洗策略]
```

## 四、第二层：分块策略

### 教学目标

让学生理解没有万能的分块策略，选择策略的依据是文档类型和查询意图的匹配。

> 核心认知：同一个策略在不同场景下效果天差地别。

### 知识内容：五种主要分块策略

| 策略 | 原理 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|---------|
| 固定字符数切分 | 按字数硬切，可设重叠区 | 简单可控 | 可能在句子中间截断 | 内容均匀、结构松散的文档 |
| 语义切分 | 基于句子embedding相似度判断边界 | 语义完整 | 计算成本高 | 对语义完整性要求高的场景 |
| 文档结构切分 | 按标题、段落、章节等结构边界切分 | 保留上下文逻辑 | 依赖文档有清晰结构 | 说明书、报告等层级文档 |
| 递归字符切分 | 按优先级依次尝试不同分隔符 | 在自然边界切分，实践最广泛 | 参数调优有一定复杂度 | 通用场景默认推荐 |
| 父子块切分 | 召回用小块，返回LLM用大块 | 兼顾精准召回和完整上下文 | 实现复杂，存储成本更高 | 需要精准定位且上下文重要的场景 |

### 核心工具：分块策略可视化实验台

#### 使用时机（两阶段）

**第一阶段——自由探索（建立直觉）：**
用平台预置文档试验不同策略，没有对错，目的是通过视觉对比建立对各策略特点的直觉感知。

**第二阶段——决策支撑（做出选择）：**
学生针对自己项目的实际文档类型，在实验台上对比测试，基于观察结果做出策略选择并填入决策文档。

实验台贯穿整个阶段三，而不是只出现一次。

#### 实验台界面设计

```
┌─────────────────────────────────────────────────────────┐
│  分块策略可视化实验台                                     │
├──────────────┬──────────────────────────────────────────┤
│  左侧控制区   │  右侧可视化区                            │
│              │                                          │
│  文档选择    │  原始文档预览（颜色高亮显示切分边界）       │
│  · 预置文档A │  ┌──────────────────────────────────┐   │
│  · 预置文档B │  │[chunk1]这是第一块的内容，讲述了... │   │
│  · 上传自己的│  │[chunk2]这是第二块，与上一块有50字  │   │
│              │  │符重叠...                          │   │
│  策略选择    │  │[chunk3]...                        │   │
│  ○ 固定字符数│  └──────────────────────────────────┘   │
│  ○ 语义切分  │  每个chunk可点击查看详情                  │

│  ○ 递归字符  │  切分统计                                │

│              │  · 平均块大小：312字符                   │
│  参数调节    │  · 最小/最大：45/589字符                 │

│  [====] 500  │                                          │
│  overlap     │  ⚠️ 系统检测到的问题                     │
│  [==]  50    │  · 第3块在句子中间截断                   │
│              │  · 第7块只有45字符，可能过短             │
│  [应用策略]  │                                          │
│              │  [与上一策略对比]                        │
└──────────────┴──────────────────────────────────────────┘
```

#### 核心交互设计

- **实时刷新**：切换策略或拖动参数滑块，右侧立即更新，颜色高亮直观展示边界变化
- **左右对比**：点击"与上一策略对比"，左右分屏显示两种策略的切分结果差异
- **问题自动标注**：系统自动标注截断位置、过短块、过长块
- **适用场景说明**：每种策略旁边有"为什么这个文档推荐/不推荐这个策略"的实时提示

## 五、第三层：向量化与存储

### 教学目标

建立向量化的基本直觉，理解向量数据库的存在价值，掌握平台级的模型选择和配置操作。

> 核心认知：向量化是把文字的语义转换成数学空间里的位置——意思相近的文字，在这个空间里距离更近。

### 知识内容

**Embedding模型概念：**
- 什么是Embedding，为什么需要它
- 平台推荐模型及选择理由（不做深度横向对比）

**向量数据库基本概念：**
- 为什么普通数据库存不好向量
- 向量数据库的核心能力：相似度搜索
- 了解常见选型（概念层，不做深度选型）

**索引构建：**
- 索引是什么，为什么需要
- 性能与精度的基本权衡（概念层）

### 教学方式：向量空间可视化

把高维向量降维到二维平面展示，让学生亲手输入句子，看到语义距离：

```
输入三组句子：

A："这批零件的漏检率很高"
B："质检过程中经常出现漏检"
C："今天天气很好"

↓ 向量化后在二维空间的位置：

        • A
      • B            意思相近，距离很近

                        • C    意思不同，距离很远
```

学生亲手输入不同句子，观察语义相近/相远的句子在空间中的位置关系，直觉自然建立。

### 模型选择设计

平台采用"推荐模型 + 说明理由"的方式，不要求学生深入理解模型选型：

```
知识库语言配置：
● 中文为主    → 推荐：bge-m3
              原因：在中文语义理解基准测试中表现最佳，
                    支持最长8192 token输入

○ 英文为主    → 推荐：text-embedding-3-small
○ 中英混合    → 推荐：bge-m3（兼容双语）

[查看模型详细对比 ↗]（链接到外部资料，不在平台内展开）
```

## 六、第四层：召回策略

### 教学目标

理解不同召回策略的原理、优劣和适用场景，能够基于项目实际情况选择和调优召回配置。

> 核心认知：召回策略决定"用什么方式找答案"，不同策略各有盲区，实际项目往往需要组合使用。

### 知识内容：四种主要召回策略

| 策略 | 原理 | 擅长 | 盲区 |
|------|------|------|------|
| 向量召回 | 基于语义相似度 | 模糊查询、自然语言问题 | 精确关键词、专有名词、数字 |
| 关键词召回（BM25） | 基于词频和逆文档频率 | 精确词匹配、型号、代码 | 无法理解语义，同义词失效 |
| 混合召回 | 两者加权融合 | 覆盖面最广，效果最稳定 | 多一个权重参数需要调优 |
| 重排序（Reranking） | 召回后用精准模型重新排序 | 提升最终结果相关性 | 增加延迟，作为后处理层叠加 |

### 核心工具：召回策略可视化实验台（分块实验台扩展）

召回测试与分块策略共用同一个实验台，切换到"召回测试"视图：


#### 核心交互设计

- **三列并排展示**：同一查询，三种策略结果同屏对比，差异一目了然
- **权重实时调整**：混合权重滑块拖动，结果即时刷新
- **策略盲区自动标注**：系统自动检测并提示每种策略的失效情况
- **预置刁钻测试集**：专门设计能暴露各策略弱点的查询集，引导学生主动发现盲区

### 召回效果评估：Hit Rate为核心指标

#### 评估方式（决策层定位）

阶段三使用**平台预置的演示知识库**来进行Hit Rate体验，目的是让学生理解评估指标的含义和使用方法，而不是测试自己真实构建的知识库（真实构建在阶段四完成）。

```
平台预置演示知识库（制造业质检场景）：
  · 已按标准流程构建好的知识库实例
  · 配置了不同的召回策略供对比测试
  · 内置标准测试集（对学生不可见）

学生操作：
  · 选择不同召回策略组合
  · 调整召回参数
  · 点击运行评估，观察Hit Rate变化
  · 理解为什么不同配置导致不同结果
```

**学生不知道测试集内容**，通过观察不同配置下的Hit Rate变化，理解参数调整对召回效果的影响规律。

#### 评估结果展示

```
运行评估结果：

  向量召回    Hit Rate: 75%  （15/20命中）  ████████░░
  关键词召回  Hit Rate: 60%  （12/20命中）  ██████░░░░
  混合召回    Hit Rate: 85%  （17/20命中）  █████████░

失败案例分析（混合召回，3个未命中）：

  ✗ 问题：Q3漏检率具体数字是多少？
    原因：精确数字查询，向量权重过高导致关键词匹配不足
    建议：提高关键词召回权重

  ✗ 问题：[问题2]
    原因：[原因]

  ✗ 问题：[问题3]
    原因：[原因]
```

**失败案例是教学价值最高的部分**——学生看到具体哪个问题失败了、为什么失败，比看一个百分比数字学到的更多。

#### 自由测试入口

学生可以向演示知识库输入任意问题，直接看不同策略的召回结果对比，培养对召回质量的主观感知——真实项目里不会有人给你现成的测试集，主观判断力同样重要。

#### 评估结果指导决策

```
演示知识库评估结果：混合召回 Hit Rate 85%

系统检测到：
向量权重0.7时，有3个精确数字查询失败

💡 学习要点：
  · 混合召回在大多数场景下优于单一策略
  · 精确数字查询需要更高的关键词召回权重
  · 你的项目文档中是否有大量精确数字？
    如果有，建议在阶段四构建时将关键词权重调高至0.4
```

学生基于评估体验填写召回策略决策项，带着有依据的决策进入阶段四执行。

## 七、第五层：效果评估与迭代

### 教学目标

建立系统性的知识库诊断思路框架，让学生在阶段四真实构建知识库时，遇到问题知道如何定位和处理，而不是手足无措。

> 核心认知：知识库不是配置完就结束的，第一版几乎不会是最好的版本。掌握诊断思路比掌握所有参数更重要。

### 前置案例教学（必经环节）

**通过三个预置案例，让学生在进入阶段四之前先见过三类问题长什么样。**

每个案例对应一类问题，结构固定：

```
┌─────────────────────────────────────────────────────┐
│  预置案例：问题类型一 · 召回不到                      │
├─────────────────────────────────────────────────────┤
│                                                     │
│  STEP 1：问题现场还原                                │
│  展示一个"坏的知识库"评估结果                        │
│  Hit Rate 45%，展示具体失败案例：                    │
│  "用户问：零件漏检率如何统计？召回结果：[空]"         │
│                                                     │
│  STEP 2：引导诊断（交互式）                          │
│  "答案在知识库里吗？"    [点击查看] → 在的           │
│  "答案块被召回了吗？"    [点击查看] → 没有           │
│  "为什么没被召回？"      [展开分析]                  │
│  → 召回Top-K设置为3，正确答案在第5位被截断            │
│                                                     │
│  STEP 3：修复演示                                    │
│  调整Top-K参数，重新评估，Hit Rate从45%升至72%        │
│                                                     │
│  STEP 4：规律总结                                    │
│  识别特征：命中率低，但答案确实存在于知识库            │
│  常见原因：Top-K过小 / 召回策略选错 / 分块切断了答案  │
│  优先检查项：先验证答案是否在库中，再查召回配置        │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 三类问题诊断框架

三个预置案例教学完成后，学生掌握以下诊断地图：

```
问题类型一：召回不到（该有的答案没找到）
────────────────────────────────────────
识别特征：Hit Rate低，召回结果为空或完全不相关
诊断路径：
  1. 答案块是否存在于知识库？
     否 → 数据清洗过度过滤，回第一层检查
     是 → 继续往下
  2. 分块是否把答案切断了？
     是 → 回第二层调整chunk_size或overlap
     否 → 继续往下
  3. 召回策略是否匹配查询类型？
     否 → 回第四层调整策略
     是 → 检查Top-K是否过小

问题类型二：召回错了（找到的不是正确答案）
────────────────────────────────────────
识别特征：Hit Rate低，召回了内容但与问题不相关
诊断路径：
  1. 知识库是否有大量相似但不同的内容？
     是 → 数据去重/分类，回第一层
  2. 分块是否过大导致不相关内容混入？
     是 → 缩小chunk_size，回第二层
  3. 向量模型是否对该领域语义理解不准？
     是 → 考虑更换模型，回第三层

问题类型三：召回对了但答案质量差
────────────────────────────────────────
识别特征：召回了正确的块，但内容不完整或语义断裂
诊断路径：
  1. 分块是否把完整答案切成了两块？
     是 → 调整chunk_size或增加overlap，回第二层
  2. 原始数据本身是否质量有问题？
     是 → 补充或修复数据，回第一层
  3. 是否需要父子块策略保留更多上下文？
     考虑 → 回第二层调整分块策略
```

### 决策输出：知识库风险预判

三个预置案例学习完成后，学生针对自己的项目填写风险预判：

```
知识库风险预判

基于对三类问题的理解，预判你的项目可能遇到的风险：

召回不到的风险：
  · 可能原因：[结合自己项目的数据情况分析]
  · 预防措施：[打算在阶段四构建时如何规避]

召回错误的风险：
  · 可能原因：[...]
  · 预防措施：[...]

答案质量差的风险：
  · 可能原因：[...]
  · 预防措施：[...]
```

这份风险预判会在阶段四构建知识库时显示在左侧面板，提醒学生关注自己预判的风险点。

### 进入阶段四的条件

```
✅ 完成条件（全部满足才能进入阶段四）
   · 完成五层知识体系的学习
   · 完成三个预置案例教学
   · 提交知识库配置决策文档（五项决策均已填写）
   · 完成知识库风险预判
```

不设Hit Rate门槛——阶段三是决策层，理解和决策质量才是评估标准，真实的Hit Rate在阶段四构建后才能测量。

## 十、待确认事项

> 阶段三设计已达成共识（v1.1定位更新后），以下为开发阶段需进一步细化的技术决策

1. **向量空间可视化的降维算法**：使用t-SNE还是UMAP？两者在直观性和计算速度上有权衡。
2. **实验台的预置文档选择**：使用什么文档作为分块和召回的演示素材，要能清晰展示策略差异。
3. **演示知识库的构建规范**：演示知识库需要预置多少文档、多少测试问题，才能让Hit Rate体验有足够的说服力。
4. **决策文档的评审机制**：阶段三的决策文档是否需要AI评审，还是只要填写完整就可以进入阶段四？
5. **代码原理展开的深度**：各配置项的"查看原理"展开内容，需要设计技术说明的详细程度和示例代码规范。
