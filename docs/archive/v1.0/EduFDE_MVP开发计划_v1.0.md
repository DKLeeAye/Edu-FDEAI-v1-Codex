# EduFDE · MVP开发计划
# MVP Development Plan

> 版本：v1.0 | 状态：规划中 | 日期：2026-04-28
> MVP成功标准：演示者操作，院校老师观看完整五阶段流程后愿意签合同

---

## 一、MVP范围定义

### 做什么

```
✅ 核心演示流程（必须做）
  · 完整的五阶段学习流程，每个阶段可交互
  · 一套完整实验场景包（制造业质检AI）
  · 阶段一：AI客户真实对话，支持2轮拜访
  · 阶段二：AI评审官真实追问，三个文档串行
  · 阶段三：分块/召回可视化实验台，决策文档输出
  · 阶段四：Dify路径完整跑通（低代码路径优先）
  · 阶段五：Dify路径交付文档
  · 基础用户体系：学生+教师两个角色
  · 基础评分展示：各阶段有得分，综合得分雷达图
  · 学习画像：完成后生成基础版画像报告

✅ 演示配套（让老师看到产品价值）
  · 教师端：查看学生进度和得分（只读）
  · 一个完整的演示账号（预置好进度节点）
  · 界面设计要完整，不能是裸UI
```

### 不做什么

```
❌ 暂不做（推迭代）
  · 阶段四代码路径（LangGraph路径）
  · 院校管理员角色和License管理
  · 教师评分功能（只读查看）
  · 通知系统
  · 多实验场景包（只做制造业质检一个）
  · 学生互评
  · 数据导出
  · 邮件通知
```

---

## 二、开发阶段划分

MVP分为四个开发阶段，每个阶段结束都有可运行的产出：

```
阶段一：地基（约2周）
  项目初始化、基础架构、用户体系、数据库

阶段二：核心AI能力（约3周）
  AI网关、LangGraph智能体、阶段一完整实现

阶段三：完整流程（约4周）
  阶段二三四五的实现、前端完整界面

阶段四：打磨与演示准备（约1周）
  流程联调、演示账号配置、UI细节打磨

总计：约10周
```

### 目标
项目能跑起来，用户能登录，数据库结构完整。

## 七、开发顺序原则

### 优先级决策依据

```
P0（阻塞性）：没有这个其他功能无法开发
  · 项目初始化、数据库、用户体系、AI网关

P1（演示核心）：演示时最有说服力的环节
  · 阶段一AI客户对话（最直观展示AI能力）
  · 阶段二AI评审追问（展示教学深度）
  · 学习画像报告（演示终态价值）

P2（流程完整性）：需要但不是最亮眼的
  · 阶段三可视化实验台
  · 阶段四新手村和任务包
  · 阶段五交付文档

P3（配套支撑）：演示时会用到但不是焦点
  · 教师端进度查看
  · 评分展示
  · 演示账号配置
```

### 遇到阻塞的处理原则

```
Claude Code开发过程中遇到技术阻塞时：
  1. 优先保证P0和P1功能完整
  2. P2功能可以简化UI但不能砍功能
  3. P3功能如果时间不够可以用mock数据撑
  4. 任何时候都要保证：能走完一遍完整演示流程
```

## 八、Claude Code开发策略

### 模块开发顺序建议

每次启动Claude Code工作时，建议按以下方式组织任务：

```
单次工作session建议范围：
  · 一个完整的后端API模块（如stage1.py全部接口）
  · 或一个完整的前端页面/组件（如阶段一工作区）
  · 不要跨越前后端同时开发，容易失去焦点

每个模块开发前必须做的事：
  · 确认数据库表结构（对照平台底层能力文档）
  · 确认API接口定义（对照技术架构文档）
  · 确认UI交互细节（对照对应阶段设计文档）
```

### 关键设计文档索引

开发各模块时对应参考的设计文档：


### 测试策略

```
MVP阶段的测试重点：
  · 每个阶段完成后手动走一遍完整流程
  · AI智能体的prompt需要反复测试调优
    （特别是AI客户和AI评审官）
  · 关键API写基础的单元测试（防止改动引入回归）
  · 不追求测试覆盖率，演示前做完整手动测试
```
