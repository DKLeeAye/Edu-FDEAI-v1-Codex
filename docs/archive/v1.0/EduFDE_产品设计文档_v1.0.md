## 一、产品定位

### 1.1 一句话描述

**EduFDE** 是一个面向高校（尤其是应用型本科）的 AI 项目全流程虚拟实训平台，以 FDE（Full-flow Delivery Engineering，全流程交付工程）理念为核心，引导学生走完从售前需求挖掘到智能体开发、部署交付的完整 AI 项目链路。

### 1.2 核心价值主张

| 对比维度 | 传统 AI 课程 | 库帕森等工具 | **EduFDE** |
|---------|------------|------------|-----------|
| 覆盖范围 | 单点知识/单一环节 | 售前打单工具 | 全流程闭环实训 |
| 使用对象 | 学生被动听课 | 销售/售前工程师 | 学生主动操作 |
| 交互形式 | PPT+视频 | 工具化使用 | 引导式虚拟实验 |
| 实操深度 | 几乎没有 | 非教育设计 | 每个环节可动手 |
| 评估体系 | 考试 | 无 | 全程过程画像+评分 |

### 1.3 目标用户

**主要用户：**
- 应用型本科院校学生（大二~大四，有基础编程能力）
- 使用场景：AI 相关专业课、实训课、毕业设计准备

**次要用户：**
- 授课教师（课程管理、学生评估）
- 院校采购决策者（院长、教务处）

### 1.4 商业模式（初步）

- **To B SaaS**：向院校按年授权，包含账号数量和存储资源
- **联合共建**：与院校合作开发实验教材，共享版权收益
- **渠道分销**：定底价，开放渠道加价空间

## 二、FDE 理念解读（产品核心）

FDE（Full-flow Delivery Engineering）是整个产品的灵魂，需要在产品设计中贯穿体现。

### FDE 全流程五个阶段

```
[售前需求挖掘] → [需求拆解分析] → [知识库搭建] → [智能体开发] → [部署交付验收]
```

每个阶段学生需要：
1. **理解**：这个环节在真实项目中的意义和产出
2. **方法**：使用什么方法论和框架
3. **工具**：使用哪些真实生产级工具
4. **实操**：亲手完成环节任务
5. **评估**：输出物是否达到质量标准

## 三、核心产品形态

### 3.1 整体布局：虚拟实验室

参考成熟虚拟实验平台的设计哲学：

```
┌─────────────────────────────────────────────────────────┐
│  顶部导航：项目信息 | 当前阶段进度条 | 学生信息           │
├──────────────┬──────────────────────────────────────────┤
│              │                                          │
│  左侧面板    │         右侧主操作区                      │
│  （引导栏）  │                                          │
│              │  根据当前阶段动态渲染对应工作区            │
│  · 阶段说明  │                                          │
│  · 步骤列表  │                                          │
│  · 当前提示  │                                          │
│  · 知识点    │                                          │
│  · 检查点    │                                          │
│              │                                          │
├──────────────┴──────────────────────────────────────────┤
│  底部工具栏：AI助手 | 资料库 | 提交检查点 | 帮助          │
└─────────────────────────────────────────────────────────┘
```

### 3.2 左侧引导面板（核心设计）

这是产品最核心的差异化设计，类似"实验操作手册"的数字化版本：

- **阶段进度树**：可视化展示五个阶段，当前位置高亮
- **步骤卡片**：每个步骤有"目标说明 + 操作提示 + 成功标准"
- **知识点气泡**：遇到专业概念时可展开学习卡
- **AI 导师**：内嵌 AI 助手，只能在当前阶段上下文中回答问题（有意限制，防止直接给答案）
- **检查点锁定**：完成当前步骤的关键动作后，才能进入下一步

### 3.3 右侧工作区（动态渲染）

根据当前所在阶段，右侧工作区渲染不同的交互界面：

| 阶段 | 右侧工作区内容 |
|------|--------------|
| 售前需求挖掘 | AI 模拟客户对话窗口 + 需求记录画布 |
| 需求拆解分析 | 结构化拆解模板 + AI 辅助填写 + 可视化需求图 |
| 知识库搭建 | 文件上传 + 数据清洗 + 知识库配置界面 |
| 智能体开发 | 工作流画布（嵌入 Dify/自研）+ 代码辅助 |
| 部署交付验收 | 部署配置向导 + 演示运行 + 验收报告生成 |

## 四、五大阶段详细设计

### 阶段一：售前需求挖掘

**教学目标：** 让学生理解如何通过 FDE 方法论从客户那里挖掘真实需求，而非听到什么就做什么。

**核心工具：AI 模拟客户系统**

```
系统设计：
- 预设多个行业场景包（制造、医疗、零售、教育、金融等）
- 每个场景有一个"AI 客户角色"，有固定背景、痛点、预算约束
- AI 客户不会主动说出完整需求，需要学生用正确问题挖掘
- 学生提问质量会被评估（是否触达痛点、是否澄清边界等）
```

**学生操作流程：**
1. 选择行业场景包（或教师指定）
2. 阅读背景材料（公司介绍、行业简介）
3. 与 AI 客户进行需求访谈对话
4. 实时记录需求要点到结构化表单
5. 系统评估访谈质量，给出反馈

**关键设计细节：**
- AI 客户有"隐藏信息层"，只有被问到才会透露
- 设置时间限制（模拟真实会议场景）
- 支持回放和复盘

**输出物：** 需求访谈记录表（结构化，带 AI 质量评分）

---

### 阶段二：需求拆解与分析

**教学目标：** 学会将模糊的客户需求拆解为可执行的技术方案要素。

**核心工具：结构化拆解工作台**

```
拆解框架（FDE方法论）：
- 业务场景定义
- 数据来源与质量评估
- AI 能力边界界定
- 技术可行性分析
- 交付标准定义
```

**学生操作流程：**
1. 导入上一阶段的需求访谈记录
2. 使用模板逐项填写拆解内容
3. AI 助手辅助：对填写内容提出追问和质疑
4. 生成需求分析报告草稿
5. AI 评估完整性和合理性

**关键设计细节：**
- 模板不能直接全填 AI 生成，AI 只辅助不代劳
- 设置"必答项"和"加分项"区分
- 支持与同学互评（未来迭代）

**输出物：** 需求分析报告 + 技术路线草图

---

### 阶段三：知识库搭建

**教学目标：** 理解 RAG 知识库的构建逻辑，掌握从原材料到可用知识库的完整流程。

**核心工具：知识库工作站**

```
系统提供：
- 行业原材料包（PDF/Word/网页内容，按行业场景预置）
- 数据清洗工作台（可视化展示质量问题）
- 分块策略配置（Chunk 大小、重叠度等）
- 向量化测试（输入问题，看召回结果）
- 质量评估仪表盘
```

**学生操作流程：**
1. 获取平台提供的行业原材料包（或自行上传补充）
2. 在数据清洗工作台处理问题数据
3. 配置分块策略
4. 触发向量化处理
5. 测试知识库召回质量
6. 迭代优化直到通过质量检查点

**关键设计细节：**
- 将技术概念（向量化、召回率等）用可视化方式呈现
- 设计"质量得分"实时反馈，让学生知道自己的知识库好不好
- 支持多策略对比实验

**输出物：** 可用的知识库实例 + 质量报告

---

### 阶段四：智能体开发

**教学目标：** 掌握 AI 智能体的构建方法，能够将需求转化为可运行的 AI 应用。

**核心工具：智能体开发环境**

这是技术难度最高的阶段，提供两条路径：

**路径 A：低代码拖拉拽（面向基础薄弱学生）**
- 内嵌 Dify/Coze 工作流界面（iframe 集成或 API 集成）
- 提供预置节点库：LLM 节点、知识库节点、工具节点、条件判断等
- 模板市场：常见场景的工作流模板可直接导入修改

**路径 B：AI Coding 辅助开发（面向有编程基础学生）**
- 内嵌代码编辑器（Monaco Editor）
- AI 编程助手（Claude API 加持）
- 调试控制台：实时查看 API 调用、Token 消耗等

**学生操作流程：**
1. 根据需求分析报告，选择开发路径
2. 设计智能体的对话流程 / 工作流
3. 连接上一阶段搭建的知识库
4. 配置 Prompt 工程（有模板辅助）
5. 测试用例验证
6. 达到验收标准

**关键设计细节：**
- 两条路径的学生都要理解底层逻辑，不能只会拖拉拽
- 提供"黑盒/白盒"切换视图
- 记录开发过程中的关键决策（供评估）

**输出物：** 可运行的 AI 智能体应用

---

### 阶段五：部署交付与验收

**教学目标：** 理解 AI 应用从开发到生产的完整交付链路，培养交付意识。

**核心工具：部署向导 + 验收模拟**

```
部署演练内容：
- 容器化打包（Docker 基础操作引导）
- 环境变量配置
- 服务启动验证
- 简单的健康检查配置
```

**客户验收模拟：**
- AI 扮演客户角色，学生向"客户"演示自己的产品
- 客户会提出现场问题和修改意见
- 学生需要快速响应并调整

**学生操作流程：**
1. 完成部署配置（平台提供沙箱环境）
2. 运行验收测试用例
3. 向 AI 客户做产品演示
4. 生成交付报告
5. 平台输出完整项目画像

**输出物：** 部署完成的应用 + 项目交付报告 + 个人学习画像

## 五、平台底层能力设计

### 5.1 用户体系

```
角色：
- 超级管理员（平台运营方）
- 院校管理员（学校IT/教务）
- 教师（课程管理、学生评估）
- 学生（核心用户）

权限模型：
- 教师可创建/管理课程实验
- 教师可查看所有学生进度和评分
- 学生只能看到自己的数据
- 院校管理员管理账号和资源配额
```

### 5.2 课程/实验管理系统

```
实验包结构：
- 元数据（名称、难度、预计时长、适用专业）
- 行业场景包（AI客户设定、背景材料、原材料数据）
- 阶段配置（每个阶段的检查点、评分权重）
- 参考答案（教师可见，用于评估参考）
- 评分规则（自动评分 + 教师主观评分）
```

### 5.3 进度追踪与评分系统

**自动评分维度：**
- 检查点完成率（硬性指标）
- 各阶段输出物质量（AI 评分）
- 操作时间效率
- 工具使用的合理性

**学生画像数据：**
- 每个阶段的时间分布
- 知识点掌握热力图
- 弱项识别与学习建议
- 项目完整度评分

### 5.4 AI 能力层

平台内嵌多处 AI 能力，统一由后端 AI 网关管理：

| AI 能力 | 使用场景 | 模型建议 |
|---------|---------|---------|
| AI 模拟客户 | 阶段一对话 | Claude claude-sonnet-4-20250514（需要角色扮演能力） |
| AI 导师助手 | 全程引导 | Claude Haiku（低成本，高频调用） |
| 需求质量评估 | 阶段一二 | Claude claude-sonnet-4-20250514 |
| 知识库质量评估 | 阶段三 | 自研评估逻辑 + LLM |
| AI 编程助手 | 阶段四 | Claude claude-sonnet-4-20250514 |
| 报告生成 | 阶段二五 | Claude claude-sonnet-4-20250514 |
| 画像分析 | 结束后 | Claude claude-sonnet-4-20250514 |

## 六、技术架构设计

### 6.1 技术选型

**前端：**
- 框架：Next.js 14（App Router）
- UI：Tailwind CSS + shadcn/ui
- 状态管理：Zustand
- 实时通信：Socket.io（AI 流式输出）
- 工作流画布：ReactFlow（阶段四低代码编辑器）
- 代码编辑器：Monaco Editor（阶段四路径B）

**后端：**
- 框架：FastAPI（Python）
- 数据库：PostgreSQL（主数据）+ Redis（缓存/Session）
- 向量数据库：Qdrant（知识库阶段）
- 文件存储：MinIO（自托管对象存储）
- 任务队列：Celery + Redis（异步任务，如向量化处理）

**AI 层：**
- 统一 AI 网关：自研（管理多模型调用、Token 计费、限流）
- 主力模型：Claude API（Anthropic）
- Embedding 模型：text-embedding-3-small（OpenAI）或 bge-m3（本地）

**基础设施：**
- 容器化：Docker + Docker Compose
- 反向代理：Nginx
- 部署：Linux 云服务器（单机起步，后续可 K8s 扩展）
- CI/CD：GitHub Actions


## 八、第一个实验场景设计（制造业质检AI）

### 场景背景

**公司：** 某中型制造企业（汽车零部件）
**诉求方：** 生产部门负责人
**核心痛点：** 人工质检效率低、漏检率高、培训新质检员成本大
**期望：** 用 AI 解决部分质检问题，但不清楚能做到什么程度

### AI 客户角色设定

```
角色：张厂长
年龄：48岁
性格：务实、对技术半懂不懂、预算敏感
背景：管理工厂15年，见过不少"花拳绣腿"的IT项目
隐藏信息：
  - 工厂现有一套老旧MES系统，数据质量很差
  - 真实预算只有20万，但开口会说"你们先报方案"
  - 最担心：系统上线后员工不会用
  - 真正的痛点是：明年有个大客户审厂，质检记录要数字化
```

### 原材料包内容

- 质检报告样本 PDF（50份，含合格/不合格）
- 产品规格说明书
