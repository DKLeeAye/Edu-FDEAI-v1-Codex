## 一、阶段定位

### 教学目标

让学生从阶段三的决策文档出发，真正动手搭建一个可运行的AI智能体应用，覆盖知识库检索、业务工作流、多轮对话与记忆三个核心能力层次。

### 三个能力层次

```
第一层：RAG问答智能体
  接入知识库，能回答业务范围内的问题
  这是最基础的层次，两条路径都必须完成

第二层：有工作流的智能体
  执行多步骤业务流程，有条件判断和节点编排
  从"工具"向"智能体"进化的关键跨越

第三层：多轮对话与记忆
  记住同一用户在对话中说过的内容
  在多轮交互中保持上下文一致性
```

### 核心设计原则

**两条路径是学习深度的选择，不是能力高低的判断：**
- 低代码路径：聚焦在智能体逻辑设计上，工具是Dify
- 代码路径：同时学习底层实现原理，工具是LangGraph
- 两条路径输出物一致，评分标准统一

### 阶段在整体流程中的位置

```
阶段三输出（知识库配置决策文档）
         ↓
   【阶段四：智能体开发】← 本文档范围
         ↓
   阶段五：部署交付验收
```

### 阶段四验收边界

**本地可运行即通过，部署是阶段五的内容。**
阶段四专注在"搭出来"，阶段五专注在"交出去"，两个阶段教学目标不互相干扰。

## 三、共同基础：智能体核心概念

### 教学目标

在学生进入任何一条路径之前，建立统一的概念框架——让低代码学生知道自己在拼什么，让代码学生知道自己在写什么。

### 核心认知

**智能体不是一个模型，而是一个系统：**

```
用户输入
    ↓
[智能体大脑：LLM]
    ↓           ↓           ↓
[知识库检索]  [工具调用]  [记忆系统]
    ↓           ↓           ↓
[工作流编排：决定什么时候用什么]
    ↓
输出结果
```

LLM是大脑，知识库是记忆，工具是手脚，工作流是行为逻辑，它们组合在一起才是一个智能体。

### 教学内容

**概念对照表（低代码 vs 代码的同一概念）：**

| 概念 | 是什么 | Dify中叫什么 | LangGraph中叫什么 |
|------|--------|------------|-----------------|
| 智能体大脑 | 处理输入、生成输出的LLM | LLM节点 | LLM调用函数 |
| 知识库检索 | 从向量库中找相关内容 | 知识检索节点 | Retriever节点 |
| 工作流 | 多步骤的执行逻辑 | 工作流画布 | Graph |
| 记忆系统 | 保存对话历史的机制 | 对话变量/记忆 | State中的messages |
| 条件判断 | 根据条件走不同分支 | 条件节点 | 条件边（Conditional Edge） |

这张表在整个阶段四学习过程中始终可以在左侧面板查阅，帮助学生在两种视角之间切换理解。

## 四、低代码路径（Dify）

### 4.1 新手村：五个闯关任务

**设计原则：**
用一个极简的玩具项目串起所有基础操作，学生完成新手村时已经有过一次完整的端到端体验，进入正式任务包时不再陌生。

**每个关卡的内部结构：**

```
┌─────────────────────────────────────────────────────┐
│  新手村 关卡N：[关卡名称]                             │
├─────────────────────────────────────────────────────┤
│  目标（一句话）：完成这一关，你将学会XXX              │
│                                                     │
│  操作步骤                                           │
│  1. [步骤描述] ── 关键步骤附截图或动图指引           │
│  2. [步骤描述]                                      │
│  3. [步骤描述]                                      │
│                                                     │
│  完成验证                                           │
│  你应该看到：[描述预期结果]                          │
│  如果看不到：[常见问题和解决方法]                    │
│                                                     │
│  [我完成了，进入下一关]                              │
└─────────────────────────────────────────────────────┘
```

**"你应该看到"是关键设计**——学生操作完不知道对不对，这句话给了自我验证的标准，不需要AI判断，学生自己就能确认是否完成。

**五个关卡内容：**

```
关卡一：创建你的第一个知识库（约10分钟）
  任务：上传平台提供的测试文档（2页PDF）
        配置最简单的分块策略（固定字符数，默认参数）
        用三个测试问题验证召回
  学生收获：知道知识库是什么，知道怎么创建
  你应该看到：三个测试问题都能召回到相关内容

关卡二：创建你的第一个AI应用（约10分钟）
  任务：新建聊天助手类型的应用
        连接刚才创建的知识库
        写一句最简单的System Prompt
        在调试窗口测试对话
  学生收获：知道应用和知识库的关系，能跑通一次对话
  你应该看到：智能体能基于知识库内容回答测试问题

关卡三：认识工作流（约15分钟）
  任务：打开平台预置的工作流模板（已搭好的示例）
        看懂节点结构（不需要自己搭）
        修改其中一个LLM节点的Prompt
        运行一次查看结果
  学生收获：理解工作流基本概念，不对画布感到恐惧
  你应该看到：修改Prompt后输出结果发生了变化

关卡四：配置多轮对话（约10分钟）
  任务：在关卡二的应用里开启对话记忆
        设置记忆窗口为5轮
        测试：提一个问题，再用"刚才说的"追问
        验证智能体是否记住上下文
  学生收获：理解记忆的概念和配置方式
  你应该看到：智能体能正确理解"刚才说的"的指代

关卡五：获取应用链接（约5分钟）
  任务：发布应用，获取公开访问链接
        在浏览器里打开链接，确认可以访问
        把链接复制回我们的平台
  学生收获：知道如何交付最终成果
  你应该看到：浏览器中出现可交互的聊天界面
```

### 4.2 正式任务包

**结构化任务分解 + 关键节点指引 + 明确验收标准**

学生从头搭建，平台不提供半成品模板。

**任务一：在Dify中搭建知识库**

```
任务目标：
按照阶段三的决策文档，在Dify中真实构建项目知识库

参考输入：
· 阶段三知识库配置决策文档（左侧面板可查阅）
· 实验场景的原材料文档包

操作指引（关键节点）：
⚠️ 关键节点1：导入文档时的格式选择
   不同格式的文档在Dify中的处理方式不同，
   注意选择与原材料格式匹配的导入方式

⚠️ 关键节点2：分块参数配置
   参考阶段三决策文档中的参数选择，
   不要使用Dify默认参数

验收标准：
  ✓ 知识库创建成功，文档全部上传
  ✓ 3个标准召回测试问题结果相关
```

**任务二：搭建基础RAG问答智能体**

```
任务目标：
创建一个连接知识库的问答应用，能在业务范围内正确回答问题

操作指引（关键节点）：
⚠️ 关键节点1：System Prompt的基本结构
   至少包含：角色定义、回答范围、拒答指令
   示例结构（不是答案，是框架）：
   "你是[角色]，负责[职责]。
    只回答关于[范围]的问题。
    对于范围外的问题，请告知用户。"

⚠️ 关键节点2：知识库引用配置
   确认应用已正确关联知识库，
   测试时注意观察引用来源是否出现

验收标准：
  ✓ 应用创建成功，连接知识库
  ✓ 3个标准问题回答正确
  ✓ 1个范围外问题合理拒答
```

**任务三：设计并实现业务工作流**

```
任务目标：
将问答应用升级为有业务流程的工作流应用

操作指引（关键节点）：
⚠️ 关键节点1：工作流 vs 聊天助手的区别
   工作流适合有明确步骤的业务流程，
   聊天助手适合开放式对话，
   这个任务需要新建工作流类型的应用

⚠️ 关键节点2：四类必要节点的作用
   · 开始节点：接收用户输入
   · 知识检索节点：从知识库获取相关内容
   · LLM节点：基于检索结果生成回答
   · 结束节点：输出最终结果
   这四类节点是工作流的最小完整结构

⚠️ 关键节点3：节点间的变量传递
   每个节点的输出需要显式连接到下一个节点的输入，
   注意检查变量名是否匹配

验收标准：
  ✓ 工作流包含四类必要节点：输入、知识库检索、LLM、输出
  ✓ 工作流完整运行不报错
```

**任务四：配置多轮对话与记忆**

```
任务目标：
让智能体能在多轮对话中记住上下文

操作指引（关键节点）：
⚠️ 关键节点1：对话型应用才有记忆配置
   工作流类型不支持原生多轮记忆，
   需要在聊天助手类型的应用中配置，
   或在工作流中手动传入对话历史变量

⚠️ 关键节点2：记忆窗口的含义
   窗口=5意味着保留最近5轮对话，
   窗口过大会增加Token消耗，
   窗口过小会丢失重要上下文

验收标准：
  ✓ 记忆窗口≥5轮
  ✓ 通过标准多轮测试用例：
    第一轮问A，第三轮用"刚才说的A"追问，
    智能体能正确理解指代
```

**任务五：发布并验收**

```
任务目标：
发布应用，通过平台自动化验收测试

操作指引（关键节点）：
⚠️ 关键节点1：发布前的自检清单
   · 知识库是否已更新到最新版本
   · System Prompt是否包含拒答指令
   · 记忆配置是否已开启
   · 在调试窗口跑一遍验收测试问题

验收标准：
  ✓ 应用链接可正常访问
  ✓ 基础功能自动化测试全部通过
  ✓ 提交设计说明（工作流设计思路+Prompt设计理由）
    → AI评审，不影响通过，计入评分
```

## 五、代码路径（LangGraph）

### 5.1 新手村：理解优先，运行为辅

**设计原则：**
先读懂，再修改，最后才从头写。不要求学生一开始无中生有，通过读代码、改代码逐步建立信心。

**五个关卡内容：**

```
关卡一：理解LangGraph核心概念（约15分钟）
  方式：不是写代码，而是读懂一段最简单的LangGraph代码
  内容：平台提供代码+可视化图结构对照
        State是什么（图的共享内存）
        Node是什么（图的处理单元）
        Edge是什么（节点间的连接）
  任务：在代码注释中填写每一行的作用（填空题）
  你应该看到：填完后平台显示理解度评估

关卡二：运行第一个LangGraph程序（约15分钟）
  方式：平台提供完整的可运行代码和脚手架
  内容：一个只有两个节点的最简单Graph
        配置API Key，在本地运行
        修改一个参数（如模型温度），看输出变化
  任务：成功在本地运行并看到输出
  你应该看到：终端输出智能体的回复内容

关卡三：理解RAG在代码里长什么样（约15分钟）
  方式：展示完整RAG实现代码片段，对照Dify知识库节点
  内容：文档加载→文本分块→向量化→存储→检索
        每一步代码对应Dify中的哪个配置项
  任务：填写一处空缺代码（召回Top-K参数）
  你应该看到：修改Top-K后召回结果数量变化

关卡四：理解状态管理与记忆（约15分钟）
  方式：展示State中对话历史的实现方式
  内容：messages字段如何累积对话历史
        如何限制记忆窗口防止Token爆炸
        对照Dify的记忆窗口配置
  任务：修改记忆窗口大小的代码参数
  你应该看到：调小窗口后历史消息被正确截断

关卡五：本地运行完整Demo（约15分钟）
  方式：平台提供完整项目脚手架（含requirements.txt）
  内容：按指引配置环境变量（API Key等）
        安装依赖，运行入口文件
        在命令行与智能体进行一次完整对话
  任务：成功运行并完成一次多轮对话
  你应该看到：命令行中出现可交互的对话界面
```

### 5.2 项目脚手架设计

平台提供标准化项目模板，学生下载后在本地开发：

```
edu-fde-agent/
├── README.md              # 详细的环境配置和运行说明
├── requirements.txt       # 所有依赖，版本固定
├── .env.example          # 环境变量模板（学生复制为.env填写）
├── config.py             # 统一配置管理
├── main.py               # 入口文件（已提供，学生不需要修改）
│
├── knowledge/            # 知识库模块（学生在这里实现）
│   ├── __init__.py
│   ├── loader.py         # 文档加载（提供框架，学生填充）
│   ├── splitter.py       # 文本分块（提供框架，学生填充）
│   └── retriever.py      # 召回逻辑（提供框架，学生填充）
│
├── agent/                # 智能体模块（学生在这里实现）
│   ├── __init__.py
│   ├── state.py          # State定义（提供框架，学生填充）
│   ├── nodes.py          # 节点函数（提供框架，学生填充）
│   ├── graph.py          # Graph构建（提供框架，学生填充）
│   └── memory.py         # 记忆管理（提供框架，学生填充）
│
├── tests/                # 验收测试（平台提供，学生不修改）
│   ├── test_retrieval.py # 知识库召回测试
│   ├── test_qa.py        # 问答能力测试
│   └── test_memory.py    # 记忆功能测试
│
└── data/                 # 实验场景原材料（平台提供）
    └── [实验场景文档]
```

**脚手架设计原则：**
- 框架代码已提供，学生专注在业务逻辑的填充上
- 每个需要填充的位置有清晰注释说明要做什么
- tests目录完全由平台提供，学生不需要写测试
- 学生实现完成后运行tests，把输出结果提交平台

### 5.3 正式任务包

**任务一：实现知识库检索模块**

```
任务目标：
在state.py和nodes.py中实现基础的检索+生成流程

⚠️ 关键节点1：State的字段设计
   至少包含：用户输入、检索结果、最终回答

⚠️ 关键节点2：System Prompt的注入方式

**任务三：实现多节点工作流**

```
任务目标：
在graph.py中构建包含至少3个功能节点的完整Graph

操作指引（关键节点）：
⚠️ 关键节点1：节点函数的签名规范
   每个节点函数接收State，返回State的更新部分

⚠️ 关键节点2：条件边的使用
   当需要根据条件走不同分支时使用条件边

验收标准：
  ✓ Graph包含至少3个功能节点
  ✓ 节点间状态传递正确

**任务五：本地运行验收**

任务目标：

## 六、验收机制

### 自动化验收测试内容

```
基础功能测试（必须全部通过，否则不能进入阶段五）

低代码路径：
  · 应用链接可正常访问
  · 3个标准知识库问题回答正确（AI判断相关性）
  · 1个范围外问题合理拒答
  · 多轮测试用例通过（第三轮能理解前文指代）

代码路径：
  · pytest tests/ 全部通过
  · test_retrieval.py：3个召回测试通过
  · test_qa.py：3个问答测试+1个拒答测试通过
  · test_memory.py：多轮记忆测试通过
```

### 设计说明的AI评审

两条路径均要求提交设计说明，AI评审维度：
- 工作流/Graph的设计逻辑是否合理
- Prompt设计是否有明确的意图
- 对遇到的问题和解决方案的描述

**AI评审不影响通过，计入最终评分的加分项。**

## 九、阶段三设计文档更新说明

> 本阶段设计过程中确认了阶段三定位的重要调整，需同步更新阶段三文档

**调整内容：**
阶段三从"构建真实知识库"调整为"做出有依据的知识库决策"。

- 阶段三是**决策层**：学生在平台上完成策略分析、配置选择、效果理解，输出知识库配置决策文档
- 阶段四是**执行层**：学生带着决策文档，在Dify或LangGraph中真实构建知识库

**对阶段三具体内容的影响：**
- 可视化实验台：定位从"测试自己的真实知识库"改为"理解策略差异、做出有依据的决策"
- Hit Rate测试：使用平台预置演示知识库，让学生体验评估过程、理解指标含义
- 阶段三输出物：知识库配置决策文档（不是真实运行的知识库实例）
