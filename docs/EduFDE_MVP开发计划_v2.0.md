# EduFDE MVP 开发计划 v2.0

> 状态：v2.0 草案  
> 上位依据：`EduFDE_终局路线图与MVP切分_v2.0.md`  
> 目标：在保留终局平台地基的前提下，完成可演示的五阶段最小闭环

---

## 一、MVP 成功标准

演示者可以用一个学生账号完整走通：

```text
需求访谈与问题发现
→ 方案定义与可行性判断
→ 知识工程决策
→ 智能体实现与测试
→ 交付验收与运维说明
→ 学习画像
```

教师账号可以查看学生进度、阶段结果和基础画像。

院校老师观看后能理解：

- 这不是普通 AI 课程平台。
- 学生确实经历了 AI 智能体项目交付全过程。
- 教师可以组织课程、查看过程、评价结果。
- 平台具备扩展为完整教学系统的基础。

## 二、开发阶段划分

### 阶段 A：平台地基

目标：

系统能跑起来，数据模型保留终局地基。

任务：

- 前后端项目初始化
- Docker Compose
- PostgreSQL/Redis/MinIO
- Alembic
- 用户登录
- 基础角色
- tenant/institution/course 作用域
- 实验包版本模型
- Artifact 模型
- AI Gateway 基础
- AI 调用日志

完成标志：

- 学生/教师可登录。
- 演示实验包可初始化。
- 能创建课程和学生 session。

### 阶段 B：阶段一核心体验

目标：

完成最有说服力的 AI 客户访谈体验。

任务：

- 制造业质检 AI 客户 Prompt
- AI 客户状态管理
- 教学六关卡
- 实战两轮拜访
- 拜访间整理
- 访谈记录 Artifact
- 阶段一 AI 评估
- 信息覆盖雷达图

完成标志：

- 学生能完成阶段一。
- AI 客户角色稳定。
- 阶段一输出可进入阶段二。

### 阶段 C：阶段二与阶段三

目标：

完成从访谈到方案，再到知识工程决策的链路。

任务：

- 阶段二三份文档
- 文档保存为 Artifact
- AI 评审追问
- 红黄灯机制
- 黄灯债务最小模型
- 阶段三数据识别练习
- 分块实验台
- 召回实验台
- 知识工程决策文档

完成标志：

- 前三阶段可连续走通。
- 黄灯债务能从阶段二带到阶段三。
- 阶段三输出可指导阶段四。

### 阶段 D：阶段四与阶段五

目标：

完成 Dify 路径和最终交付闭环。

任务：

- 阶段四共同基础
- Dify 新手村
- Dify 正式任务
- Dify 应用链接提交
- 标准题验收基础版
- 设计说明 Artifact
- 阶段五交付文档
- 验收记录
- 已知限制说明

完成标志：

- 学生能提交 Dify 应用。
- 学生能完成交付文档。
- 五阶段状态 completed。

### 阶段 E：教师端与演示打磨

目标：

支持完整演示。

任务：

- 教师课程列表
- 班级学生进度
- 学生详情
- Artifact 查看
- 基础学习画像
- 演示账号
- 演示数据
- UI 打磨
- 部署上线

完成标志：

- 学生账号可完整演示。
- 教师账号可查看结果。
- 演示环境稳定。

## 五、MVP 技术决策建议

### 5.1 AI 流式输出

优先使用 SSE。

WebSocket 后置到通知或多人协作。

### 5.2 AI 客户实现

MVP 可用服务状态机 + AI Gateway。

LangGraph 可用于后续增强，不强制第一版复杂编排。

### 5.3 阶段二编辑器

MVP 建议采用结构化表单优先，局部支持富文本。

原因：

- 更易评审
- 更易保存 JSON
- 更易生成 Artifact
- 更易映射 Rubric

### 5.4 阶段三实验台

MVP 坚持演示和决策层定位。

优先预置文档和预置知识库，不做复杂真实构建。

### 5.5 Dify 验收

MVP 可先做：

- 链接可访问检查
- 标准问题人工/AI 辅助评审
- 设计说明评审

如果 Dify API 接入成本可控，再增强自动验收。

## 六、测试策略

### 6.1 后端

重点测试：

- 认证
- 作用域过滤
- 实验包版本绑定
- session 阶段推进
- Artifact 保存
- AI Gateway 日志
- 黄灯债务

### 6.2 前端

重点测试：

- 登录路由保护
- 实验室阶段切换
- 阶段一对话
- 阶段二文档保存
- 阶段三实验台交互
- Dify 链接提交
- 教师端进度查看

### 6.3 AI

重点人工调试：

- AI 客户角色稳定
- 隐藏信息不泄露
- AI 评审不乱判
- AI 导师不直接给答案

## 八、开发风险

### 8.1 AI 客户体验风险

优先投入调试。

阶段一是 MVP 最强卖点。

### 8.2 文档编辑器复杂度风险

优先结构化表单，降低富文本复杂度。

### 8.3 阶段三实现过重风险

坚守决策层，不做真实知识库生产构建。

### 8.4 Dify 外部依赖风险

准备手动验收 fallback。

### 8.5 数据模型过度设计风险

只实现最小结构，但保留终局字段和边界。
